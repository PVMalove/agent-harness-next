# FastAPI и React для Веб-консоли

**Статус: ACCEPTED (2026-11-05).** Эпик #862. Документ дополняет ADR 0028 и заменяет его
решения о транспорте, поставке и браузерном фронтенде. Остальные положения ADR 0028 —
один Сервер консоли на проект, TUI и браузер как клиенты, discovery-файл, токен, проверки
Host и Origin, job, подтверждения, журнал, live-события и принятый остаточный риск —
продолжают действовать.

## Контекст системы

ADR 0028 выбрал для Сервера консоли собственный asyncio-транспорт на `asyncio.start_server`,
`h11` и `websockets`, а для браузера — серверный рендер Jinja2 и тонкий JavaScript. Этого
достаточно для прототипа, но владелец принял два дополнительных требования:

- браузерные экраны должны повторять утверждённые макеты без расхождения в интерактивных
  состояниях, включая drag & drop, модальные окна, фильтры и переподключение;
- backend должен быть расширяемым модульным приложением с явными границами, контрактами,
  наблюдаемостью и воспроизводимой поставкой, а не набором обработчиков в одном файле.

При этом сохраняются ограничения эпика: один локальный сервер на проект, только `127.0.0.1`,
токен, offline-поставка, отсутствие внешних ресурсов, TUI остаётся клиентом того же протокола,
Rust runtime и audit-цепочка не меняются.

## Действующий контракт

### 1. Backend: FastAPI

Сервер консоли реализуется на Python 3.12+ как **модульный монолит**:

```
console_server/
  domain/          # снимки, команды, job, approvals, курсоры; без FastAPI
  application/     # use cases и порты
  infrastructure/  # процессы, трекеры, ledger, discovery, journal, WebSocket
  api/             # FastAPI-роуты, зависимости, сериализация
```

- HTTP и WebSocket обслуживает **FastAPI + Uvicorn**; схемы и валидация — **Pydantic v2**.
- FastAPI используется только на границе `api/`. Домен и application-слой не импортируют
  FastAPI, Starlette или Uvicorn.
- Один экземпляр приложения обслуживает один проект. Discovery-файл, токен, idle-таймаут,
  проверки Host/Origin, ограничения методов и защитные заголовки сохраняются из ADR 0028.
- WebSocket-контракт остаётся совместимым с TUI-клиентом: снимки, job, вывод с курсором,
  подтверждения, решения человека, live-события и `cursor_expired`.
- Job принадлежит серверу, переживает отключение клиента и не завершается вместе с ним.
  Одна мутирующая команда на проект; чтения и live-потоки не блокируются.

### 2. Frontend: React + TypeScript

Браузерный клиент — отдельное SPA:

- **React + TypeScript + Vite**;
- React Router для маршрутов, типизированный клиент WebSocket и HTTP;
- CSS и design tokens берутся из `docs/design/web-console-mockups/` и поставляются как общий
  слой, а не переписываются в CSS-in-JS;
- сборка статическая; FastAPI отдаёт `index.html`, JS, CSS и локальные шрифты;
- Node нужен только на этапе сборки. В runtime Node нет;
- CSP запрещает внешние ресурсы; шрифты и иконки локальные;
- ru/en через существующий слой перевода; переключение не перезагружает страницу;
- при обрыве WebSocket показывается переподключение, после восстановления клиент читает
  пропущенное по курсору;
- состояния connected / reconnecting / no server / error / empty остаются частью контракта.

### 3. Контракты и типы

- HTTP-контракт описывается OpenAPI, который генерирует FastAPI.
- WebSocket-сообщения описываются Pydantic-схемами и экспортируются в JSON Schema.
- TypeScript-типы генерируются из OpenAPI/JSON Schema в CI; расхождение ломает сборку.
- Версия протокола входит в handshake и в сообщения; несовместимое изменение требует новой
  версии и теста совместимости с TUI.
- Ошибки имеют стабильный машинный код и человеческое сообщение; UI не разбирает текст ошибки.

### 4. Поставка и зависимости

- FastAPI, Uvicorn и Pydantic закреплены единым пином и дублируются в dev-группе; тест
  проверяет равенство версий.
- `harness console --web` запускает приложение через `uv run --with` (или упакованный entry
  point) и печатает URL с токеном; `--no-open` сохраняется.
- Frontend собирается `npm ci && npm run build`; артефакты `dist/` входят в пакет и
  проверяются на отсутствие внешних URL.
- Jinja2 и собственный `h11`-транспорт из ADR 0028 удаляются после миграции.
- Офлайн-запуск без кэша зависимостей даёт текстовый `harness health` и код 1, как раньше.

### 5. Совместимость с TUI

- TUI остаётся Python-клиентом WebSocket-протокола и не переписывается на React.
- Смена транспорта не меняет семантику сообщений; сетевые тесты прогоняют один и тот же
  контракт против FastAPI-приложения.
- Пока миграция не завершена, второй сервер не поднимается: FastAPI заменяет транспорт
  ADR 0028, а не работает рядом с ним.

### 6. Безопасность

Сохраняются все правила ADR 0028: loopback, случайный порт, токен в HttpOnly cookie,
Bearer для TUI, проверка Host/Origin на handshake, только GET/HEAD для страниц, строгие
заголовки и CSP без внешних ресурсов. Дополнительно:

- статические файлы SPA отдаются с теми же защитными заголовками;
- cookie `SameSite=Strict`, `HttpOnly`, `Secure` не требуется для loopback, но проверяется
  политика браузера;
- ошибки FastAPI не раскрывают traceback, пути и токены;
- загрузка произвольных файлов и внешних URL запрещена.

### 7. Тестирование

- **Сетевой шов:** FastAPI-приложение на эфемерном порту; HTTP-клиент `httpx`, WebSocket-клиент
  `websockets`. Проверяются токен, Host/Origin, снимки, job, переподключение, подтверждения,
  «занято», журнал, live-события и `cursor_expired`.
- **Контракт:** Pydantic/JSON Schema и сгенерированные TypeScript-типы; тест на дрейф.
- **Frontend:** Vitest для чистых функций, Playwright для маршрутов, модальных окон, drag & drop,
  reconnect и визуальных снимков 1440/390.
- **Визуальная регрессия:** эталонные снимки утверждённых макетов; расхождение выше согласованного
  порога блокирует PR.
- Ручная приёмка человеком сохраняется для новых экранов и спорных состояний.

## Альтернативы

- **Оставить asyncio/h11 + Jinja2 (ADR 0028).** Меньше зависимостей и нет Node, но выше цена
  поддержки интерактивного UI и слабее контракты/наблюдаемость.
- **C#-монолит с DDD.** Не выбран: появился бы второй runtime и второй домен команд/снимков,
  а TUI и Python/Rust-слой остались бы снаружи. Это отдельная программа миграции, а не
  транспорт веб-консоли.
- **FastAPI + Jinja2.** Компромисс, но не даёт компонентной модели и типизированного состояния
  для сложных экранов; владелец выбрал React/TS.

## Операционные последствия

- Появляются Node/npm и lockfile только для сборки; нужен CI-шаг сборки и проверки артефактов.
- Новые пины FastAPI, Uvicorn и Pydantic; удаляются Jinja2 и собственный h11-транспорт.
- Растёт размер поставки за счёт JS/CSS/шрифтов; кэш и offline-проверка обязательны.
- Появляется риск дрейфа React-компонентов от макетов; его закрывают общий CSS, Playwright и
  обязательная визуальная приёмка.
- Закрытые тикеты #864–#871 описывают прежний транспорт; их результаты сохраняются как история,
  а действующая реализация переносится отдельным тикетом миграции.
- #882 переписывается под React/TS; #883–#889 и #914–#915 получают React-маршруты вместо
  Jinja2-страниц.
- TUI-контракт и Rust runtime не меняются.
