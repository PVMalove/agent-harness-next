# Каталог FMEA как условие для remedy-шага

**Статус: ACCEPTED (2026-11-08).** Эпик #1022. Дополняет ADR 0007 (поле `.remedy` у `HarnessError`).

## Контекст системы

У ошибок харнесса есть `remedy`: в Python около 1150 мест `remedy=` в 84 файлах, в Rust около 170
упоминаний, у хуков 27 `reason_code`. Ни один remedy не проверен: нет записи о том, как возникает
отказ, и нет теста, что подсказка возвращает работу в строй. У Python-ошибок нет стабильного кода,
только `message` и `remedy`, поэтому привязать подсказку к отказу нечем.

## Действующий контракт

- Remedy-шаг положен ошибке только для **проанализированного режима отказа**: запись каталога FMEA
  плюс автотест восстановления («сломать, применить сценарий, повторить, отказ ушёл»). Без записи
  подсказка остаётся подсказкой (legacy), а при неудаче наступает остановка (ADR 0032).
- Каталог — текстовый TOML в пакете харнесса, одна таблица на режим: `id` (GUID, uuid4, создаётся
  скриптом, руками не пишется), `title` (уникальный slug, например `git-timeout`, можно
  переименовать), `mode`, `detection`, `recovery` (текст «сделай X и повтори»), `test`
  (идентификатор автотеста), `residual_risk`.
- Скрипт генерирует из каталога модуль `FmeaId(StrEnum)`: имя члена из `title`, значение — GUID.
  Режим `--check` падает, если модуль разошёлся с каталогом, и входит в `scripts/verify.py`.
- `HarnessError` принимает `fmea` (`FmeaId`) или `remedy`: ровно одно. С `fmea` текст remedy берётся
  из каталога; `except` сохраняет структуру и передаёт `fmea=FmeaId.X` вместо копии строки.
- CLI печатает `FMEA: <guid> (<title>)`; ответ хука добавляет поле `fmea` рядом с `reason_code`.
- SQLite собирается из каталога только для чтения и запросов (`harness fmea show`). Он не
  коммитится и не участвует в обработке ошибок.
- `INTERNAL_INVARIANT_REMEDY` остаётся терминальным и ведёт в RCA: у внутреннего инварианта нет
  проанализированного сценария по определению.

## Рассмотренные варианты

- **Каталог в `runtime.db`.** Отвергнут: это operational state чекаута с единственным writer
  (ADR 0020), он не поставляется в целевые проекты, проверка ссылок в CI потребовала бы запущенного
  runtime, а строка не проходит ревью в PR.
- **Закоммиченный бинарный `.db`.** Отвергнут: в PR не видно строк, конфликты слияния неразрешимы.
- **Локальная записываемая БД с экспортом.** Отвергнут: два источника истины.
- **Реестр по `reason_code`.** Отвергнут: он есть только у хуков и Rust, у Python-ошибок его нет.

## Операционные последствия

- Существующие remedy остаются подсказками, пока их области не переведены; миграция идёт отдельными
  тикетами по областям (хуки, Python вне `orchestration`, остаток `orchestration`).
- Поле `fmea` в Rust `ErrorBody` меняет протокол и выносится в отдельный эпик.
- Новый remedy-шаг без записи и теста восстановления не принимается.
