# Жизненный цикл тикета в эпике: `status::done` и закрытие при слиянии

**Статус: ACCEPTED (2026-11-08).** Эпик #1022. Меняет формулировку шага «merged and closed» в
руководстве по меткам и «separate release action» в руководстве по поставке.

## Контекст системы

Тикет эпика вливается в `integration/<service-or-team>`, а сама интеграционная ветка позже уходит
в `base_branch`. Метка `status::done` отсутствовала: выполненный тикет оставался с
`status::in-progress`, и «выполнен» выражалось только закрытием issue. PR интеграционной ветки в
`base_branch` не открывал ни один скилл.

## Действующий контракт

- Разработчик пишет в чат, что смерджил PR тикета. Агент доказывает слияние по состоянию PR (слит,
  SHA головы равен SHA ветки), заменяет `status::in-progress` на `status::done`, закрывает тикет
  через CLI, переводит зависимые тикеты из `status::blocked` в `status::ready` и убирает worktree.
  Метка ставится до закрытия: на тикете всегда ровно одна `status::*`.
- Тикет закрывается при слиянии в `integration/*`, а не при слиянии интеграционной ветки: так
  снимаются нативные связи `blocked_by`.
- **Интеграционный PR** — любой PR с head `integration/*` (метка `pr::integration`, без `type::*`).
  Режим `to-pull-requests` открывает его, когда закрыты все дочерние тикеты и `qa-gate` прошёл на
  голове ветки; в проекте с opt-in Release Gate добавляется `integration next`. В теле стоит
  `Closes #<epic>` только если цель — `base_branch`, иначе `Related to #<epic>`; влитые тикеты
  перечислены без закрывающих слов. После подтверждённого слияния агент проверяет закрытие эпика и
  ставит ему `status::done`. Ветку `integration/*` он не удаляет, а спрашивает.
- PR тикета (`pr::ticket`) наследует `type::*` тикета.

## Рассмотренные варианты

- **Держать тикеты открытыми до интеграционного PR:** нативные `blocked_by` не снимаются, цепочки
  зависимостей внутри эпика встают до слияния всей ветки.
- **Оставить «закрыт = done» без метки:** состояние не видно в фильтрах и отчётах по меткам.
- **`Closes` на все дочерние тикеты в интеграционном PR:** для уже закрытых тикетов это ничего не
  делает и сбивает читателя.

## Операционные последствия

- Правила закрытия и разблокировки в `to-pull-requests` обновляются под новую последовательность.
- Колонка `done` на доске задач строится по закрытому состоянию и не зависит от метки.
- Удаление веток после слияния остаётся передачей разработчику, пока баг #1023 (хук блокирует
  удаление) не исправлен.
