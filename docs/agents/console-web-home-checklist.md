# Ручная приёмка Home веб-консоли

Основание: [ADR 0028](../adr/0028-web-console.md) и принятый
[макет](../design/web-console-mockups/execution-console-prototype.html#home).
Проверять реальный `harness console --web` в изолированном проекте. Не включать токен,
bootstrap URL, cookie или содержимое discovery-файла в скриншоты, отчёты и логи.
После первого входа адрес должен содержать только `/?lang=ru` или `/?lang=en`.

Автоматические HTTP/WebSocket-проверки находятся в `tests/console/test_web.py`,
`test_web_assets.py` и `test_server.py`; отдельный тест подтверждает побайтное равенство CSS.
Они не доказывают выполнение JS, применение CSP и визуальное соответствие макету.
Основной список ниже остаётся открытым: частичное наблюдение не закрывает весь пункт.
В PR указать браузер, viewport, масштаб, commit SHA, результат и ссылки на снимки без credentials.

## Подтверждённые наблюдения desktop-приёмки #882

- [x] Реальный сервер после bootstrap открывает чистый `/?lang=ru`; Home получает
  настоящий снимок и показывает подключённое WS-соединение.
- [x] RU/EN переключают заголовок, навигацию, headings и метки соединения; в английском
  контексте показаны Name/Tracker/Package/Skills. Сообщения проверок остаются данными.
- [x] Значки статуса не перекрывают идентификаторы. В контексте короткие строки фактов,
  компактное `—` для отсутствующих значений и явное объяснение недоступности.
- [x] Контекст расположен над задачами. Health показывает счётчики, цветную полосу
  и внутреннюю прокрутку списка проверок. Browser console не содержит ошибок/предупреждений.

Наблюдения переданы координатором после просмотра реального приложения. Локальные снимки
без credentials: `.harness/.sandboxes/reports/issue-882/home-ru-desktop.jpg` и
`home-en-health.jpg`. Узкий экран, 200% zoom и точные переходы/тайминги reconnect не проверены.
Пауза процесса на 50 секунд завершилась новым снимком после восстановления, но промежуточные
состояния не наблюдались; это не считается полной проверкой reconnect.

## Полный список для PR

- [ ] На широком экране: шапка, три группы и 13 пунктов меню, подвал; контекст на всю
  ширину над последними задачами. Заголовки и геометрия соответствуют макету.
- [ ] На узком экране и при 200% масштабе: текст читается, содержимое не перекрыто;
  мобильное меню открывается, закрывается по фону и Esc. Сворачивание desktop-меню
  сохраняется после перезагрузки; выбранный раздел обозначен `aria-current`.
- [ ] Все 13 пунктов открываются; Home показывает факты, остальные разделы — честную
  заглушку. Сочетания g/d/o/? и Escape работают вне полей ввода.
- [ ] В Home есть «Требует внимания», «Контекст», «Последние задачи», «Здоровье»,
  «По областям», список проверок и статическая схема «Контур Harness 2.0.0».
  Внутри health прокручивается список, страница остаётся компактной.
- [ ] Полоса health имеет четыре цвета, сумма счётчиков согласована со снимком.
  Нулевой total не даёт NaN; skipped остаётся пропуском. Пустой список проблем
  не объявляет все проверки успешными; усечённый список показывает число выведенных/всех.
- [ ] Нет вымышленных branch/tracker, задач, ролей, возраста, runtime-ready/schema/audit.
  Отсутствующие HEAD map, memory и active_batches обозначены недоступными; null не становится 0.
  Версия пакета не выдаётся за установленную версию проекта. Контур — схема без live-статуса.
- [ ] RU/EN меняют подписи, `html lang`, aria и состояния соединения; ссылки переключения
  не содержат токена. Без query используется HARNESS_CONSOLE_LANG, неизвестное значение даёт ru.
  Произвольные id, версии и сообщения проекта остаются данными.
- [ ] В DevTools нет CSP-ошибок; загружаются только локальные CSS/JS и WebSocket на
  фактическом loopback-порту. Нет CDN, inline script/style, внешних шрифтов и eval.
  Иконки и SVG-полоса видны. Текст проекта и problem.message не исполняется как HTML.
- [ ] Первый ответ даёт connected. Офлайн обновляется последовательно с интервалом
  15 секунд после ответа; «Проверить» отправляет force. Онлайн включается явно,
  автоматические запросы не повторяют сетевые health-проверки.
- [ ] Разрыв WS сохраняет последний снимок с предупреждением об устаревании;
  reconnect использует задержку 0,5–8 секунд. После восстановления приходит новый
  correlated Home response, исчезает stale и возобновляется выбранный режим.
  Поздний ответ старого соединения не заменяет актуальный снимок.
- [ ] При отсутствии снимка/долгом отказе показано unavailable и ручной повтор;
  зависший сокет закрывается по timeout, фоновое восстановление продолжается.
  Уход со страницы закрывает соединение и таймеры. Новый порт/токен сервера требует нового CLI URL.
- [ ] Первый bootstrap выдаёт HttpOnly/SameSite=Strict cookie и чистый redirect;
  повтор без cookie отклонён, с cookie не выдаёт новую. HEAD и GET с телом не погашают
  выдачу. Native Bearer после входа браузера по-прежнему работает.
- [ ] Два проекта на разных loopback-портах работают с общим cookie jar: выдаются
  разные `console_token_<port>`, посторонние корректные cookie не мешают первому входу.
  Устаревшая cookie заменяется только корректным первым bootstrap; повтор без
  действующей сессии отклонён. Legacy `console_token` остаётся совместимой,
  дубликаты cookie и смешанные Authorization/Cookie отклоняются. Это уточнение
  архитектуры принято при ручной приёмке #882: browser cookie не имеет port scope.

Полный clean-room и Rust QA выполняются независимо на финальном SHA. Разработчик проверяет
затронутые Python-контракты и `make lint`; этот checklist не заменяет release QA.
