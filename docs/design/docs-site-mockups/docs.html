Быстрый старт

Установите глобальный слой, подключите harness к проекту и проверьте окружение. Всё, что нужно для первого запуска, — Python 3.12+ и Git.

beta обновлено 5 ноября 2026 8 минут чтения

Что вы получите

Agent Harness Next — это набор скиллов, hooks и контекстных документов, который разворачивается в проект как проверяемый snapshot. После установки проект живёт автономно: skills и hooks работают через нативные механизмы Claude Code и Codex, а оркестрация использует Rust runtime и локальный runtime-store.

i

Проект в раннем доступе. Публичные страницы описывают текущую архитектуру: Rust runtime и runtime-store. Перед установкой в рабочий проект сделайте backup и проверьте требования.

Требования

КомпонентТребование
Python3.12 или новее; uv для окружения проекта
Git2.40+; проект — Git-репозиторий
RuntimeClaude Code или Codex; для веб-консоли — браузер
ОСLinux; Windows — через поддерживаемый runtime и named pipe
ОпциональноDocker или rootless Podman для контейнерного worker/QA

1. Установите глобальный слой

Глобальный слой ставится один раз для выбранных runtime и даёт команды start-project и integrate-project.

python3 bin/install-global.py --target-home "$HOME" \
  --runtime claude --runtime codex

В PowerShell:

python bin\install-global.py --target-home $HOME `
  --runtime claude --runtime codex

2. Подключите harness к проекту

Для нового проекта используйте start-project, для существующего — integrate-project. Прямая установка в Git-репозиторий:

python3 harness/bin/harness.py init /path/to/repository \
  --capability engineering-suite \
  --project-type software --stack python --base-branch main --language ru \
  --qa-gate-command "make test"

python3 harness/bin/harness.py health /path/to/repository
✓

Проверьте вывод health. В разделе «Оркестрация» должно быть authority=runtime-store и schema_version=4, а критические hooks — подключены. Если проверка не проходит, health назовёт причину и команду исправления.

3. Проверьте verification

В harness developer и review запускают только затронутые проверки, а QA — полный clean-room прогон на финальном SHA. План проверки закрепляется в brief, а его digest — в approval.

python3 .harness/orchestration/coordinator.py --repo . dispatch preflight
python3 .harness/orchestration/coordinator.py --repo . qa run --batch <id>
python3 .harness/orchestration/coordinator.py --repo . ledger validate --full

4. Настройте профиль hooks

Профиль задаётся в .harness/project.json и не может быть понижен агентом. standard — поведение по умолчанию, minimal — быстрый цикл, strict — fail-closed границы для чувствительных путей.

{
  "hook_policy": {
    "profile": "standard"
  }
}

harness health показывает действующий профиль, источник, эскалации и подключение критических hooks для каждого runtime.

5. Публикация и Release Gate

Publish разрешён только по подтверждённой паре {candidate_sha, target_sha} с полным clean-room QA или CI, принятым integration collect-ci. После merge дерево целевой ветки сверяется с candidate_tree_sha.

!

Focused, failed-only и кэшированные результаты не подтверждают пару. Если target ушёл вперёд, нужен новый полный прогон.

Справочник

Полный список команд и полей конфигурации появится в отдельных страницах. Ниже — минимальный набор для первого запуска.

CLI

КомандаНазначение
harness init <repo>Установить snapshot в новый проект
harness adopt <repo>Установить поверх существующих скиллов
harness update <repo>Обновить managed-файлы и hooks
harness health <repo>Проверить окружение, hooks, ledger и память
harness diff <repo>Показать расхождения с залоченным snapshot
harness cleanup <repo>План и применение очистки sandboxes
harness uninstall <repo>Полное удаление harness из проекта

Конфигурация

Проектные настройки живут в .harness/project.json и .harness/orchestration.json. Минимальный фрагмент:

{
  "language": "ru",
  "base_branch": "main",
  "qa_gate_commands": ["make verify"],
  "hook_policy": { "profile": "standard" }
}

Схемы и валидаторы — в harness/project/project.schema.json и harness/orchestration/orchestration.schema.json.
