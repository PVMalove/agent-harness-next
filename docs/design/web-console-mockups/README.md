# Веб-макеты Harness Console 2.0.0

Единственный актуальный интерактивный макет веб-консоли. Старые HTML-макеты и audit-viewer удалены.
Это прототип: данные демонстрационные, действия выполняются в памяти и ничего не записывают.

## Навигация · шаг 1

Согласован вариант **A**: 12 стабильных разделов в трёх группах. Роли и статусы — фильтры
внутри «Хода работы» и «Оркестрации», а не отдельные пункты меню.

Меню сворачивается до колонки иконок кнопкой-шевроном в шапке и разворачивается обратно; состояние
хранится в `localStorage`. В свёрнутом виде остаются иконки, active state, числовые счётчики и
tooltip-подписи. На мобильной ширине вместо этого работает drawer.

| Группа | Разделы |
| --- | --- |
| Обзор | Главная, Диагностика, Обновление, Проект |
| Работа | Ход работы, Оркестрация, Отчёты, Публикация |
| Контекст | Harness, Repo Map, Настройки, Справка |

Полная карта маршрутов, фильтры и соответствие 2.0.0: [navigation-a.md](navigation-a.md).

Сейчас [консоль](execution-console-prototype.html) на `#home` показывает **Главную** в тёмной
сине-серой палитре.

## Состояния соединения

В шапке есть демонстрационный переключатель состояния: **online → reconnect → нет сервера → ошибка → пусто**.
`online` показывает обычный экран; `reconnect` — баннер переподключения со stale-предупреждением; остальные
три состояния заменяют содержимое объяснением и действием повтора. Сеть не используется, все состояния
переключаются в памяти.

## Источники шагов

В «Ходе работы» показаны два источника: Claude Code со структурированными шагами и Codex с явной
пометкой **«структура недоступна»**. Для Codex открывается только plain-хвост лога; thinking и raw JSON
не показываются.

## Главная · шаг 2

Экран собран в тёмной сине-серой палитре; полного реестра batch/dispatch на нём нет:

- health summary `42 пройдено · 1 внимание · 2 ошибки · 11 пропущено` и сегментная полоса;
- «Здоровье» — один компактный блок: summary, области в две колонки и проверки; видны три
  проверки, остальные прокручиваются внутри блока. Donut и отдельная панель проверок убраны;
- переключатель **Офлайн / Онлайн**; онлайн в макете не выполняется и не превращает 11 пропусков
  в успех;
- версия `2.0.0 pre-release`, установлено `1.5.1`; `runtime-store`, schema 6, generation 36,
  audit 306, cutover 27.10.2026;
- навыки: 32 установлено, 259 managed files, 1 capability, 1 drift;
- «Контур Harness 2.0.0» — одна диаграмма готовности в стиле процесса: policy → IPC → Rust
  runtime → SQLite WAL / Supervisor / Audit chain; отдельный Repo Map-график убран;
- контекст проекта — отдельный полноширинный блок сверху над задачами, прокручивается вместе
  со страницей; внутри — GitHub-иконка и строка трекера. Панель «Обновление 2.0.0» убрана;
- «Последние задачи» — три сессии и маршрут активной #716: Architect выполняется, Developer /
  Review / QA / PR не начаты. Это короткая сводка, а не полный экран Оркестрации.

`Проверить` перечитывает демонстрационный снимок.

## Диагностика · шаг 3

[`#diagnostics`](execution-console-prototype.html#diagnostics) — рабочий экран проверок:

- сводка `42 · 1 · 2 · 11` и сегментная полоса, всего 56 проверок;
- переключатель **Офлайн / Онлайн**; онлайн в макете не выполняется и не скрывает пропуски;
- список 7 ключевых проверок из 56: фильтры `Все / Проблемы / Пропущено / Пройдено`,
  поиск по названию, области и деталям;
- master-detail: выбранная проверка показывает статус, область, что проверено, почему важно,
  что сделать, команду-источник и время;
- для пропущенной проверки — отдельное предупреждение «пропуск не успех» и действие
  «Запустить онлайн»;
- **«Исправить»** в деталях открывает план исправления с командой; в макете команда не
  выполняется, для пройденной проверки кнопка disabled;
- **«Экспорт»** скачивает JSON текущей выборки: summary, режим, фильтр, запрос и проверки;
- «Проверки» и «Детали проверки» — равные колонки и равная высота на десктопе;
- действия ведут в обновление, Harness, Repo Map или перечитывают демонстрационный снимок.

- «Версии» и «Что изменится» — один компактный блок; «Режим обновления» и «План» — второй;

- «Обновить» открывает подтверждение, но не запускает процесс; «Проверить заново» перечитывает
  демонстрационный diff;
- миграция runtime-store: backup → schema 3→6 → cutover → health; result-панель пустая до запуска.

## Оркестрация · шаг 8

[`#orchestration`](execution-console-prototype.html#orchestration) — нативный экран вместо
исторического Execution Dashboard:

- сводка 3 батча / 3 dispatch / 2 активны / 1 QA-внимание;
- схема пайплайна по мотивам референса, но не 1:1, тремя подписанными группами:
  `01 PLAN & APPROVE`, `02 BUILD / REVIEW + FINDINGS`, `03 EVIDENCE & PUBLISH`;
  путь approve плана → Architect → Developer → Code review → QA → approve QA →
  итоговый отчёт → публикация → PR; находки Code review и QA возвращаются в Developer,
  дефект идёт в итоговый отчёт; 11 узлов, 13 связей;
- три карточки батчей с мини-маршрутом из 5 шагов;
- таблица dispatch с фильтрами по роли и статусу;
- QA lane #716: fail → pass → wait;
- у каждого узла счётчик текущих задач, сверху — разбивка 1 в работе / 1 blocked / 1 waiting / 0 QA;
- палитра оркестрации — violet / cyan / lavender / mint, без красного и жёлтого;
- подписи легенды убраны; акценты групп и узлов остаются, правый блок 03 расширен;
- ссылки в Ход работы и Отчёты; роли и статусы — фильтры, не пункты меню;
- схема имеет собственный горизонтальный скролл на узкой ширине и не расширяет страницу.

### Аналитика оркестрации

В `#orchestration` добавлены вкладки **Схема / Поток / Качество / Runtime / Гейты**
и KPI-строка: WIP/oldest, rework, QA first-pass, stale+unknown, flow efficiency.

- **Поток**: WIP по состояниям (срез, не тренд), старение по бакетам, cycle time p50/p95,
  ожидание review/QA/approve/PR, throughput и flow efficiency.
- **Качество**: retry по причинам и маршрутам, review/QA returns, first-pass, defect escape,
  severity findings, verification mix, evidence heatmap, Release Gate matrix, local QA attempts.
- **Runtime**: heartbeat/stale/unknown/lost, QA lease и fencing, recovery checks, holds, MTTR,
  execution states и operations.
- **Гейты**: линейный график approval latency за сутки (p95 vs average), график p50/p95
  по гейтам и компактная таблица gate / p50–p95 / oldest / rejected–conditional–stale /
  handoff; на мобильной ширине строки перестраиваются в две колонки.
- **Все тикеты** — таблица внизу: тикет, название и batch, стадия/роль, статус, возраст,
  обновление; 6 демонстрационных записей.

Тренды не подменяются демо-данными: WIP и aging показывают текущий срез, а throughput
помечен как demo. Палитра — violet / cyan / lavender / mint, без красного и жёлтого.

## Ограничения

- Нет сервера, WebSocket, авторизации и записи решений: только демонстрация интерфейса.
- QA evidence — санитизированный демонстрационный текст, не реальный artifact.
- Переключателя ru/en нет; строки пока русские.
- Screen reader и 200% zoom вручную не проверялись.
- `make lint` покрывает Python, а не HTML/CSS/JS макета; для черновика запускается self-test.
