# Доска задач: ручная приёмка #914

Основа: [шаг 14](README.md#доска-задач--шаг-14), маршрут `#board` прототипа.
Реализация: React-маршрут `#/board` из общего AppShell, общий `execution-console.css`, данные —
снимки сервера `task_board.specs` и `task_board.snapshot` (#913). Перенос карточки (drag & drop и
селектор статуса) добавлен в #915: его чек-лист — в разделе «Перенос карточки: ручная приёмка
#915» ниже.
Чек-лист предназначен для ручной приёмки владельцем; автоматические проверки её не заменяют.

- [ ] Заголовок «Доска задач», подзаголовок, факты: название и ветка спеки, число задач, время
      снимка; действия «Обновить» и «Оркестрация».
- [ ] Переключатель спек показывает «#n · название — N задач»; выбранная спека сохраняется в
      браузере и восстанавливается, пока трекер её перечисляет.
- [ ] Четыре KPI: «Открыто … из N задач», «С блокерами», «Активный batch», «Снимок»; при
      недоступном журнале «Активный batch» показывает «нет данных».
- [ ] Поиск, приоритет P0–P2, «Без блокеров» и «Сбросить» сужают карточки; «X из Y» считает
      видимые карточки, счётчик колонки — число её видимых карточек.
- [ ] Пять колонок: «Бэклог», «Готово к работе», «В работе», «Review / QA», «Готово» с
      подсказками макета; пустая колонка подписана «пусто».
- [ ] Карточка: номер, приоритет, заголовок, первая строка What to build, команда, чип
      «dispatch: роль», «блокеров: N» или «без блокеров», «критериев: N», ссылка «Открыть».
- [ ] Событие журнала по тикету или batch открытой доски перечитывает снимок с `force` без
      перезагрузки страницы; без событий доска перечитывается по TTL снимка (60 с).
- [ ] Модальное окно: «#n · спека», заголовок, метки, story points, issue, PR, ветка, текущий
      статус и селектор «Сменить статус» (#915); вкладки «Контекст», «Acceptance (N)», «Промпт».
- [ ] «Копировать» копирует промпт, а на вкладке Acceptance — пронумерованные критерии; при
      отказе буфера обмена текст показан и выделен для ручного копирования.
- [ ] HTML, скрипты и Markdown из тикета показаны как текст; ссылка не http(s) не выводится.
- [ ] Состояния «Спек пока нет», «На доске нет задач», «Обновление доски» и баннер «Трекер
      недоступен» с причиной, сообщением и возрастом снимка соответствуют макету.
- [ ] ru/en переключается без перезагрузки; все подписи доски переведены.
- [ ] На 390 px колонки прокручиваются горизонтально внутри доски, страница не переполняется;
      модальное окно помещается в экран.
- [ ] Шрифты, цвета, интервалы и диалог сверены с макетом на 1440/390 px.

## Отличия от демонстрационного макета

Демо-значения макета (номера спек и тикетов, сообщение трекера, «2 мин», ссылки на репозиторий)
в консоль и фикстуры не попадают: фикстуры собираются из синтетических данных через
`TaskBoardService` (`tests/console/test_web_fixture_task_board.py`). Поле без источника в снимке
показывает «нет данных». Счётчик колонки считает карточки, видимые после фильтров, как в макете.
Селектор демо-состояния и баннер «Идёт мутирующая команда» не переносятся. Перенос карточки
(#915) не использует демо-логику макета: правила считает сервер (`card.moves`) и перепроверяет
команда `harness ticket-status`, заметка диалога называет трекер проекта, а не GitHub макета.
Toast макета заменён строкой уведомления на странице.

## Перенос карточки: ручная приёмка #915

Основа: `boardTransition` и `requestBoardMove` прототипа (`execution-console.js`), классы
`drop-ok`/`drop-no` и `board-confirm*` общего `execution-console.css`. Визуальное соответствие
макету проверяет владелец по этому чек-листу на 1440 и 390 px: по ADR 0029 Playwright проверяет
структуру страницы и не сравнивает скриншоты.

- [ ] Во время перетаскивания карточки допустимые колонки подсвечены `drop-ok`, запрещённые —
      `drop-no`, своя колонка не подсвечена; после отпускания подсветка снимается.
- [ ] Перенос «Бэклог → Готово к работе» с открытым блокером отклоняется подписью
      «#n → «Готово к работе»: Открыты блокеры: #m, …»; без открытых блокеров открывается диалог.
- [ ] «В работе → Готово к работе» при активном batch отклоняется подписью «Активный batch …».
- [ ] Перенос в «Review / QA» и «Готово», из «Review / QA» и из «Готово», а также «Бэклог ↔ В
      работе» отклоняются текстами макета; задание при этом не запускается.
- [ ] Диалог «СМЕНА СТАТУСА»: «#n → колонка», заголовок тикета, «откуда → куда», заметка с
      трекером проекта (GitHub, GitLab или локальный трекер), кнопки «Отмена» и «Сменить статус».
- [ ] «Отмена» и Esc закрывают диалог без записи; «Сменить статус» запускает job и показывает
      «Смена статуса…», затем «#n: статус обновлён», и доска перечитывается.
- [ ] При другой мутирующей команде перенос получает отказ «Занято: <команда>»; при ошибке
      трекера — «Ошибка записи в трекер: изменение не сохранено», доска перечитывается.
- [ ] Селектор «Сменить статус» в модальном окне предлагает те же переносы и отказы, что и
      перетаскивание; запрещённые варианты помечены «✕», выбор запрещённого возвращает текущий
      статус и показывает причину в модальном окне.
- [ ] Селектор доступен с клавиатуры (Tab, стрелки, Enter) и помещается в модальное окно на
      390 px; диалог подтверждения помещается в экран, страница не переполняется по горизонтали.
- [ ] Подписи переноса, диалога и отказов переведены в ru/en и не содержат демо-значений макета.
- [ ] После успешного переноса метка `status::*` в трекере одна, прежняя снята.

## Автоматические артефакты

`tests/web/task-board.spec.ts` проверяет колонки, счётчики, карточку, модальное окно, вкладки,
четыре состояния, отсутствие горизонтального переполнения и политику CSP на 1440 и 390 px по
структуре страницы, без сравнения скриншотов.
`tests/web/task-board.test.tsx` и `tests/web/task-board-modal.test.tsx` проверяют фильтры,
живое обновление, TTL, состояния, вывод текста и копирование.
`tests/web/test_task_board_network.py` проверяет настоящее приложение FastAPI поверх ASGI с
поддельным GitHub и подписи ru/en.
`tests/web/task-board-status.spec.ts` проверяет на 1440 и 390 px подсветку колонок при
перетаскивании, отказы с причинами, диалог подтверждения, отказ «занято», ошибку записи, селектор
статуса с клавиатуры и отсутствие горизонтального переполнения — по DOM, без сравнения скриншотов
(ADR 0029); визуальное соответствие макету — ручной чек-лист выше.
`tests/web/task-board-status.test.tsx` проверяет то же поведение на уровне компонентов, а
`tests/core/test_harness_cli_ticket_status.py` — команду `harness ticket-status` с поддельными
`gh`/`glab`.
