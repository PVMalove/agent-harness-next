# Паритет Web Console с макетом: элемент → источник → статус

Основа: [execution-console-prototype.html](execution-console-prototype.html) и его
`execution-console.js` (страницы `homePage`, `diagPage`, `harnessPage`, `repoPage`, `workPage`,
`orchPage`, `reportsPage`, `publishPage`, маршруты `#recovery` и `#container-route`). Макет не
меняется. Таблица служит основой описания PR и чек-листом ручной приёмки владельцем.

Статусы:

- **ЕСТЬ** — источник уже есть в снимке консоли;
- **KERNEL** — новое поле в представлении kernel и протоколе, покрыто тестами Python;
- **НЕТ ДАННЫХ** — источника нет; на месте макета показано явное состояние «нет данных».

Демонстрационные значения макета в консоль не попадают. Клиент не пересчитывает аналитику:
числа «из N», процентили и возрасты считает kernel; на клиенте допустимы только длины списков и
группировка.

## Решения владельца

| Вопрос | Решение |
| --- | --- |
| H1 Публикация | Раскладка макета; живая панель решений ledger с подтверждениями — внутри блока «Решение человека» на вкладке «Обзор»; выбор batch над KPI, по умолчанию последний batch с отчётом review. |
| H2 Бейдж PRE-RELEASE | Показывается, только если реальная версия harness содержит semver-суффикс (`-pre`, `-rc`, `-alpha`, `-beta`…); иначе скрыт. |
| H3 Состояния соединения | Формулировки SPA про сервер консоли сохраняются; endpoint — реальный URL WebSocket; пустое состояние — своё на каждой странице. Раскладка по макету. |
| H4 Блоки без места в макете | Сначала блоки макета в его порядке, затем существующие блоки и действия консоли; подтверждения не удаляются. |
| ADR 0029 | Playwright проверяет только DOM и отсутствие горизонтального переполнения; без снимков экрана. |
