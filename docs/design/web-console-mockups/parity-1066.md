# Паритет Web Console с макетом после замечаний владельца (#1066)

Основа: [execution-console-prototype.html](execution-console-prototype.html) и его
`execution-console.js`. Макет и `execution-console.css` не менялись; переопределения консоли
лежат в `harness/console/frontend/src/styles/app.css`. Предыдущая таблица паритета —
[parity-1039.md](parity-1039.md); этот файл фиксирует постраничный аудит по замечаниям владельца
к PR #1071 и служит чек-листом ручной приёмки.

## Как проводился аудит

- Каждая страница и каждая её вкладка открыты рядом с макетом при 1440×900 и 390×844:
  консоль — production-сборка (`npm run build`) с фикстурами WebSocket, макет —
  `file://…/execution-console-prototype.html#<route>`. Снимки экрана — рабочий материал, в
  репозиторий не попадают.
- Прокручивается `main#content`, поэтому кадры сняты прокруткой этого контейнера, а не
  `fullPage`.
- Проверки в репозитории — только DOM (ADR 0029): блоки макета в его порядке
  (`tests/web/mockup-parity.spec.ts`), обход всех вкладок каждой страницы на 1440 и 390 px без
  выхода панелей за рамки, без горизонтальной прокрутки документа и без нарушений axe-core
  (`tests/web/pages.spec.ts`), структура блоков и лимиты списков в vitest.
- Демонстрационные данные макета в консоль не переносятся. Поле без источника показывает
  «нет данных» с причиной в подсказке.

Статусы:

- **OK** — совпадает с макетом без правок;
- **ИСПРАВЛЕНО** — расхождение устранено в этом batch;
- **НЕТ ДАННЫХ** — блок макета есть, источника нет; внутри блока «нет данных» с причиной;
- **ВЛАДЕЛЕЦ** — расхождение остаётся на приёмку владельца, причина в строке;
- **В МАКЕТЕ ТОЖЕ** — дефект макета, в консоли исправлен в `app.css`.
