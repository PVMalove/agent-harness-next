## 1. Название и локализация
- **Английское название:** block-dangerous-git.sh
- **Русский перевод / Суть:**

```text
Блокировка опасных Git-команд
```
## 2. Полное описание
Данный скрипт-хук (тип `PreToolUse(Bash)`) отвечает за блокировку запуска разрушительных команд Git. Он перехватывает выполнение таких команд, как `git reset --hard`, `git clean -f`, `git branch -D`, `git checkout .` и `git restore .`. Скрипт адаптирован из "git-guardrails-claude-code", но намеренно не блокирует `git push` напрямую (защита пушей в основные ветки контролируется отдельно в `block-direct-master.sh`). Логика направлена на защиту локального репозитория от случайной потери незакоммиченных изменений агентом, требуя от пользователя явного подтверждения.

Команда разбирается как shell, а не ищется по сырому тексту. Блокируется только запуск `git`: слово команды, в том числе внутри `$(...)`, обратных кавычек, `sh -c`/`bash -c`, `eval` и тела heredoc, которое подаётся в оболочку (`bash <<'EOF'`). Слова, которые на той же строке передаются в оболочку через `|`, `<<<` или `<(...)` (`echo "..." | sh`), тоже разбираются как скрипт. Упоминание той же строки в кавычках, в аргументе другого интерпретатора (`python -c "..."`) или в теле heredoc для не-оболочки (`python - <<'EOF'`) — это данные, команда проходит. Если разобрать команду не удалось (например, незакрытая кавычка), хук откатывается к поиску по сырому тексту и блокирует при совпадении.

Исключение — удаление слитой issue-ветки после слияния. Команда `git branch -D <ветка>...` проходит, только если это одна простая команда без операторов, подстановок, кавычек и глобальных опций git, и для каждой ветки `merged_branch.py` доказал слияние. Ветка должна подходить под `branch_pattern` из `.harness/project.json` и не быть защищённой (`master`, `main`, `base_branch`, `integration/*`). В трекере (GitHub или GitLab, через `gh`/`glab` с явным `-R`) должен быть слитый PR/MR этой ветки, голова которого равна SHA локальной ветки. Squash- и rebase-слияние оставляют коммиты ветки вне истории цели, поэтому слияние доказывается по состоянию PR, а не по Git. Если трекер, CLI или резолвер `.harness/health` недоступны, ответ не разобран или ветки нет, команда блокируется (fail closed) с причиной в сообщении.

Известные ограничения: хук не видит команду, которую запускает другой интерпретатор или удалённая оболочка (`python -c "os.system(...)"`, `ssh host '...'`), и содержимое файла, переданного в оболочку (`cat x | sh`, `bash script.sh`). Глобальные опции `git` (`git -C dir reset --hard`) не разбираются, как и раньше. Оболочкой считается любое слово `sh`/`bash`/`zsh`/`dash`/`ksh`/`eval` на строке, поэтому редкий пример вроде `grep bash <<EOF` с опасной строкой в теле блокируется (ложное срабатывание в безопасную сторону).
## 3. Контракты
- **Вход (Input/Brief):** Строка (через stdin), содержащая команду в формате `"command": "..."` (обычно передается инфраструктурой агента перед выполнением Bash).
- **Выход (Output/Report):** Возвращает код `0`, если опасных паттернов не найдено. Возвращает код `2` и сообщение в `stderr`, если команда заблокирована.
