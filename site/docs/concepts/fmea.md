# Каталог FMEA

Каталог FMEA хранит проанализированные режимы отказа харнесса: как отказ возникает, как его
распознать и что возвращает работу в строй. Ошибка со ссылкой на запись каталога даёт агенту
проверенный сценарий восстановления, поэтому агент повторяет шаг сам и не зовёт человека. Решение
записано в ADR 0041.

## Зачем каталог

У каждой ошибки харнесса есть `remedy`, но до каталога ни один remedy не был проверен. Каталог
вводит правило: remedy-шаг положен ошибке только для **проанализированного режима отказа**, то есть
записи каталога вместе с автотестом восстановления. Ошибка без записи по-прежнему печатает remedy,
но это лишь подсказка (legacy). Если подсказка не помогла, наступает
[остановка](error-stops.md), и её фаза RCA предлагает новую запись каталога. Поэтому тот же отказ в
следующий раз уже не останавливает агента.

## Формат записи

Каталог — файл `harness/fmea/catalog.toml` в пакете харнесса. Каждый режим отказа — таблица
`[[failure_mode]]` ровно с семью строковыми ключами; других ключей в таблице и на верхнем уровне
файла нет.

| Ключ | Содержание |
| --- | --- |
| `id` | GUID записи, uuid4 в нижнем регистре; уникален и никогда не меняется |
| `title` | уникальный slug, например `git-timeout`; его можно переименовать |
| `mode` | что отказывает и как это проявляется |
| `detection` | как харнесс обнаруживает отказ |
| `recovery` | что сделать и повторить: этот текст ошибка печатает как remedy |
| `test` | node id автотеста восстановления |
| `residual_risk` | что остаётся неустранённым |

Первая запись каталога в сокращённом виде:

```toml
[[failure_mode]]
id = "869778d3-80c0-4702-97eb-88068b2baab1"
title = "git-timeout"
mode = "Git plumbing read (`git diff`, `git show`) … hangs longer than `GIT_TIMEOUT_SECONDS` …"
detection = "… `_run_git` raises `ContextPackageError` with `fmea=FmeaId.GIT_TIMEOUT`."
recovery = "check the repository for a held Git lock or an overloaded disk, then retry"
test = "tests/fmea/test_git_timeout_recovery.py::test_git_timeout_recovers_after_the_lock_is_released"
residual_risk = "…"
```

Значения сокращены. Полную запись печатает `harness fmea show git-timeout`, а источник —
`harness/fmea/catalog.toml`.

## GUID и `title`

`id` никогда не вводится вручную. Новую запись добавляет только команда

```bash
python scripts/fmea_catalog.py new <title>
```

Она создаёт uuid4, дописывает заготовку записи с пустыми полями и перегенерирует `FmeaId`. Опции
для ввода `id` у команды нет. `title` должен соответствовать `^[a-z][a-z0-9]*(?:[-_][a-z0-9]+)*$` и
быть уникальным. Переименовать `title` можно: код ссылается на запись через GUID, а не через имя.

## Генератор `FmeaId`

Модуль `harness/fmea/ids.py` с перечислением `FmeaId(StrEnum)` генерируется из каталога и вручную не
правится:

```bash
python scripts/fmea_catalog.py generate          # перезаписать ids.py
python scripts/fmea_catalog.py generate --check  # только сравнить, код 1 при расхождении
```

Имя члена — `title` в верхнем регистре с заменой `-` на `_` (`git-timeout` → `GIT_TIMEOUT`),
значение — GUID. Имена членов должны быть уникальны, поэтому `git-timeout` и `git_timeout` вместе
существовать не могут. `scripts/verify.py` запускает `generate --check` и падает, если модуль
разошёлся с каталогом.

## Ошибка со ссылкой на каталог

`HarnessError` принимает ровно один из двух параметров: `remedy` (текст) или `fmea` (член
`FmeaId`). С `fmea` текст remedy берётся из поля `recovery` записи, а блок `except` сохраняет свою
структуру и передаёт `fmea=FmeaId.X` вместо копии строки. Неизвестный id или запись без `recovery`
дают ошибку при создании исключения. CLI печатает под remedy строку

```text
FMEA: 869778d3-80c0-4702-97eb-88068b2baab1 (git-timeout)
```

По этой строке `/implement` и `/fast-implement` отличают проверенный сценарий от подсказки: они
применяют `recovery` и повторяют шаг не больше трёх раз (ADR 0012).

## Автотест восстановления

Режим отказа считается проанализированным, только когда у записи есть автотест восстановления. Тест
вызывает отказ, применяет сценарий, повторяет шаг и проверяет, что отказ ушёл. Он помечен маркером
pytest `fmea`, а поле `test` записи хранит его node id. Образец —
`tests/fmea/test_git_timeout_recovery.py`: тест имитирует зависший `git`, проверяет, что ошибка
несёт `FmeaId.GIT_TIMEOUT` и remedy из каталога, затем «освобождает блокировку» и получает успешный
вызов. Отдельные тесты проверяют, что каждая ссылка `FmeaId` в коде есть в каталоге и что тест из
поля `test` каждой записи существует.

## `harness fmea show`

Для запросов каталог собирается в SQLite-файл `.harness/fmea.db`. Файл только для чтения, не
коммитится и не участвует в обработке ошибок.

```bash
python scripts/fmea_catalog.py db       # собрать .harness/fmea.db из каталога
harness fmea show git-timeout           # или GUID записи
```

`harness fmea show` печатает строку `FMEA: <guid> (<title>)` и поля `mode`, `detection`,
`recovery`, `test` и `residual_risk`. Если файл не собран, команда отказывает и называет команду
сборки.

## Ограничения

- Существующие remedy остаются подсказками, пока их области не переведены в каталог отдельными
  тикетами: хуки, Python вне `orchestration`, остаток `orchestration`. Поле `fmea` в JSON-ответе
  хуков появится с переводом хуков.
- Remedy нарушения внутреннего инварианта (`INTERNAL_INVARIANT_REMEDY`) ведёт в
  [фазу RCA](../skills/diagnosing-bugs.md#rca), а не в каталог: у такого отказа по определению нет
  проанализированного сценария.
- Rust runtime пока не передаёт id записи FMEA: изменение `ErrorBody` вынесено в отдельный эпик.
