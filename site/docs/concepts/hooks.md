# Hooks и профили

Hooks превращают правила процесса в проверки, которые срабатывают до действия. Правило, записанное
словами, агент может забыть; hook вернёт отказ раньше, чем команда выполнится.

## Зачем

**Запрет опасных операций.** Прямой коммит или push в защищённую ветку, мерж pull request,
разрушительная операция с историей приводят к состоянию, которое нельзя откатить одной командой.
Hook проверяет команду до запуска и отказывает.

**Защита процесса.** PR без пройденного QA выглядит готовым, хотя его не проверяли. Hook не даёт
открыть PR, пока прогон качества для текущего дерева не пройден.

**Защита метаданных.** Следы автоматизированного исполнителя в истории коммитов и в описании
изменения остаются навсегда и меняют авторство работы. Hook блокирует их до публикации.

## Три профиля

Профиль задаёт строгость поведенческих проверок: сколько предупреждений, повторных проверок и
отказов получает работа.

- `minimal`: только критические guard-ы. Подходит для быстрых правок в личном проекте.
- `standard`: режим по умолчанию. Критические guard-ы, ограниченный прогон проверок и напоминания.
- `strict`: добавляет повторную проверку чувствительных путей и отказ на границах высокого риска.

Ни один профиль, включая `minimal`, не ослабляет критические guard-ы. Строгость меняет число
подсказок и повторных проверок, но запрет опасного действия остаётся.

## Второй runtime

Hooks для обоих поддерживаемых runtime поставляются из одного набора скриптов, и критические
guard-ы у них одинаковые. Второй runtime присылает правки файлов патчем, поэтому guard-ы
подключаются группой, которая покрывает и патч, и обычную запись. Решение не зависит от того,
каким инструментом правили файл.

Если hooks этого runtime недоступны, критическую защиту дают проверки процесса в runtime и
coordinator, а `harness health` предупреждает об отсутствии hooks. Так пробел виден и не
маскируется.

## Политика как контракт

- Профиль читается только из `.harness/project.json`. Переменные окружения и параметры
  инструментов его не меняют.
- Агент не может изменить ни настройки hooks, ни ключ политики: такие правки блокируются во всех
  профилях. Политику меняет человек.
- Для отдельных путей и ролей профиль можно повысить эскалацией; понизить нельзя.
- Hook отвечает структурированно: идентификатор, профиль, решение `allow`/`warn`/`block`, код
  причины, готовая рекомендация и ссылка на доказательство. При внутренней ошибке критический
  hook блокирует действие, а поведенческий разрешает его и пишет диагностику.

При approval coordinator закрепляет digest политики. Если профиль сменили после согласования,
план и исполнение идут при разных политиках, и это видно до публикации.
