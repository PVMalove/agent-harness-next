# Code review

Ревью проверяет изменения по двум независимым осям, и их отчёты не объединяются. Код может пройти
одну ось и не пройти другую: стиль аккуратный, но сделано не то. Две оси проверяют субагенты
параллельно, от фиксированной точки: коммита, ветки, тега или merge-base.

## Standards

Ось сверяет код с задокументированными стандартами репозитория и с baseline из двенадцати
«запахов» кода Фаулера. Например: загадочное имя, дублирование, одержимость примитивами, повторяющиеся
ветвления. Запах остаётся суждением, а не жёстким нарушением, и к ошибке не приравнивается.
То, что ловят линтер, форматтер и проверка типов, ось не повторяет. Если стандарт репозитория
противоречит baseline, побеждает стандарт.

## Spec

Ось сверяет код с исходным тикетом или спецификацией: что упущено, что сделано сверх задачи
(расширение объёма) и что реализовано неверно. Если спецификацию не нашли и пользователь подтвердил,
что её нет, ось явно пропускается и не додумывает требования.

## Как это устроено

На вход ревью получает дифф от фиксированной точки и описание задачи. Два субагента получают независимые
инструкции, работают параллельно и возвращают отчёты в основную сессию. Основная сессия не правит
замечания молча, а принимает решение по каждому. Язык отчёта задаёт поле `language` в
`.harness/project.json` (по умолчанию `ru`), а не язык комментариев в коде.

Пример фрагмента отчёта:

```text
Standards — Warning
- services/reports/csv.py: Primitive Obsession (суждение) — разделитель передаётся строкой в трёх местах.
Spec — Clean
- Все пункты тикета покрыты; лишнего поведения нет.
```

## Что считается блокером

- Невыполненный критерий приёмки.
- Изменение вне объявленного объёма задачи.
- Новое поведение без теста.
- Ослабленная проверка: отключённый тест, `except: pass` вокруг проверяемого действия, проверка,
  суженная до тривиального случая.

По замечанию Standards вы принимаете решение: если оно не влияет на поведение, его можно принять как
долг. Замечание по Spec так не принимается: расхождение с задачей нужно устранить или явно
переформулировать задачу.
