# Контекст для ролей

Context Package закрепляет для роли исходники, тесты и решения. Coordinator проверяет размер и свежесть пакета до отправки. Пакет подсказывает, что читать, но не заменяет проверку результата.

[Обзор оркестрации](../../backend-orchestration.md)

## Discovery Context и Context Package {#discovery-context-context-package}

Discovery Pipeline передаёт проверенный контекст от проектирования к dispatch. `/grilling` ведёт
`Live Artifact` со списком кандидатных путей и добавляет путь только после явного согласия
пользователя. `/to-spec` сохраняет утверждённый список в эпике под
`## Relevant Files (Discovery Context)`. `/to-tickets` назначает каждый путь подходящему
tracer-bullet тикету и строит Path inventory. Один вызов дешёвой модели (advisory) может добавить
только точные зависимости из этого Path inventory. Его ответ не считается ни evidence, ни authority.

Перед первым dispatch coordinator может зарегистрировать в ledger детерминированный Context Package:

```bash
python .harness/orchestration/coordinator.py --repo . context-package register \
  --batch <batch-id> --candidate-commit <candidate-sha> \
  --symbol-graph-depth 1 --min-starting-files 5 --max-starting-files 10 \
  --max-package-tokens 60000
```

`context_builder.py` не вызывает LLM и работает по закреплённым (pinned) base и candidate commits.
Пакет содержит:

- точный diff;
- 5–10 стартовых файлов с причинами;
- ограниченный граф символов и зависимостей;
- связанные тесты;
- краткие карточки ADR и прецедентов;
- SHA-256 и размер в байтах каждого файла;
- оценку токенов с запасом.

Побайтно одинаковые файлы (например, зеркало `docs/agents/*` ↔ `harness/project/docs-agents/*`)
остаются стартовыми файлами, но оценка учитывает их содержимое один раз. Причина второй копии
называет оригинал и требует держать копии одинаковыми.

Если оценка Markdown-файла не меньше `context_package_policy.section_index_min_tokens`
(по умолчанию 20000), файл входит в пакет как оглавление. `sections` перечисляет заголовки уровней
1–3 вне fenced code с `start_line` и `end_line`. Оценка учитывает только оглавление, а роль читает
лишь нужные ей диапазоны строк. Файл без заголовков учитывается целиком.

Python-файл при том же пороге входит как индекс символов: верхнеуровневые функции, классы и методы
классов. Вложенные в функции и методы определения индекс не перечисляет. Остальной код файла
покрывают указатели `module header` (до первого определения) и `module code` (между определениями,
после последнего и блоки вроде `if TYPE_CHECKING:`), поэтому индекс ничего не скрывает. Символы,
скрытые через `repo_map_policy.redact_symbols`, остаются в заголовках маркером `[REDACTED-SYMBOL]`.
Coordinator берёт индекс, только если он дешевле файла. Файл без определений, с синтаксической
ошибкой или в другом формате учитывается целиком.

Если пакет не помещается в лимит, coordinator по одному заменяет индексом самые тяжёлые стартовые
файлы, для которых индекс можно построить, пока пакет не уложится. Новый файл, который добавляет diff, так не
сократить: его текст уже лежит в diff. Связанные тесты и ADR остаются в пакете целиком.

Карточки прямых локальных зависимостей берут сигнатуры из Repo Map. Если сигнатур нет, пакет берёт
первые 30 строк файла. Этот контекст одного уровня не зависит от графа связей: глубину графа задаёт
`symbol_graph_depth`. Если пакет не помещается в token limit и после замены файлов индексами,
сборка завершается ошибкой и не обрезает пакет молча. Legacy-флаг `--max-package-size-bytes` можно
задать для дополнительной диагностики, но он не заменяет token limit.

Запись пакета неизменяема, версионирована и проверяется по хэшу. Пакет общий для всего batch: на
одних base и candidate architect, developer и continuation sessions получают один ID пакета.
Новый пакет появляется только после нового candidate.

Coordinator не переиспользует пакет, если его зафиксированный источник из `memory.pointers` после
регистрации изменился, стал недоступен или отозван. Тогда следующий dispatch регистрирует новый пакет
с актуальными указателями. Старый пакет не меняется для уже выданных brief. Coordinator проверяет
свежесть пакета до handoff и не создаёт brief с устаревшим пакетом. Если и новый пакет устарел по
памяти, ошибка называет путь, ожидаемый и полученный `source_hash` и предлагает запустить
`harness memory rebuild .` из основного checkout или dispatch с `--no-memory`.

Brief передаёт краткую сводку: стартовые файлы, связанные тесты, прецеденты и закреплённые commits.
Полный diff хранится один раз, в пакете. Пакет не заменяет неизменяемый brief и не отменяет
обязательные self-report, heartbeat, review и QA.
