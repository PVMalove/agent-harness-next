# Как устроен Harness

Harness устанавливает в проект скиллы, правила, hooks и документы для работы с агентом.
CLI копирует выбранный состав в репозиторий; после установки проект использует собственный снимок.
Обновление ставит отдельная команда, после того как ты просмотришь изменения.

Это общая карта. Подробные инструкции — в тематических главах,
переводы контрактов — в [Справочнике](reference/translations/index.md).

## Из чего состоит установка

- **Скиллы** описывают порядок работы агента и условия вызова. Runtime обнаруживает их через
  штатные проектные пути. Скилл сам по себе не ограничивает права процесса.
- **Правила проекта** задают ветки, команды проверки, трекер и другие договорённости.
  Инженерная конфигурация хранится в `.harness/project.json`.
- **Hooks** проверяют события инструментов. Подключение зависит от runtime и доверия к настройкам;
  запись hook в файле не доказывает, что он сработал.
- **Оркестрация** при выбранной capability добавляет coordinator, роли и проверяемые переходы.
  Политики и назначения задаёт `.harness/orchestration.json`.

`.harness/skills/` содержит установленный набор. `harness.lock` закрепляет его состав,
`REGISTRY.md` помогает найти скилл. Пути `.claude/skills` и `.agents/skills` ведут к этому набору.
Подробнее читай про [обнаружение скиллов](runtime-discovery.md) и [структуру проекта](project/structure.md).

## Как выбрать состав

| Capability | Когда выбирать |
| --- | --- |
| `project-foundation` | Нужны общие скиллы исследования, обсуждения, передачи контекста и инструкций |
| `mattpocock-suite` | Нужен закреплённый upstream-набор инженерных и продуктивных скиллов |
| `engineering-suite` | Нужны проектные правила, hooks и инженерный процесс с поддерживаемыми переопределениями |
| `backend-orchestration` | Нужны отдельные роли, согласования и независимая проверка; расширяет `engineering-suite` |

Без явного выбора CLI использует `project-foundation`. Выбери нужную capability;
зависимости разрешает CLI. Поля и промпты выбора описаны в [быстром старте](getting-started/index.md).

## Установить и обслуживать

1. Для новой идеи используй [start-project](skills/start-project.md), для существующего проекта
   используй [integrate-project](skills/integrate-project.md). Сначала агент изучает задачу и задаёт вопросы.
2. До записи проверь команду `init`, `adopt` или `update`, целевой репозиторий и выбранный состав.
3. После установки выполни `health`. Флаги `--fix` и `--online` запускают отдельные действия.
4. Перед обновлением изучи `diff`. Если ты менял управляемые файлы локально, реши отдельно, что с ними делать.
5. Для удаления временных данных сначала просмотри `cleanup`. Команда удаляет файлы только с `--apply`.
   Harness целиком удаляет отдельная команда `uninstall`; она тоже сначала показывает план удаления.

Точные команды и условия находятся в [справочнике CLI](reference/cli.md),
[инструкции обновления](hooks/install-and-update.md) и [настройках проекта](getting-started/settings/index.md).
Harness не записывает значения секретов в конфиги и отчёты.

## Провести задачу

[Рабочий поток](guides/workflow.md) помогает выбрать точку входа: обсуждение идеи, готовая спецификация
или входящий тикет. Для небольшого `afk`-тикета с меткой `pipeline::fast` есть `/fast-implement`.
`/implement` использует роли и гейты `backend-orchestration`. Для ручной реализации `/to-guide`
готовит пошаговое руководство.

Разработка проходит [TDD](guides/tdd.md), [ревью](guides/code-review.md) и [QA](guides/qa-gate.md)
по выбранному маршруту. PR агент открывает только после отдельного подтверждения. Merge делает человек.
[Примеры](guides/examples.md) показывают маршруты целиком.

## Контекст и параллельная работа

[Worktree](concepts/worktrees.md) отделяет рабочую ветку и файлы задачи. Он не создаёт изоляцию
процесса, сети или учётных данных. Права worker задаются и проверяются отдельно.

[Контекст сессии](concepts/context.md) нужно сохранять в документах и трекере, чтобы другая сессия
могла продолжить работу. В оркестрации [Context Package](guides/orchestration/context.md) закрепляет
набор данных роли. Repo Map даёт карту кода, а необязательная память проекта возвращает указатели
на разрешённые источники. Если память недоступна, агент не придумывает прежние решения.
