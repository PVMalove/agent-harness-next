# block-pr-merge

## 1. Name and localization
- **English name:** block-pr-merge (PreToolUse Hook)
- **Translation / Essence:**

```text
Ban on PR/MR auto-merge / Blocking of the agent running the commands `gh pr merge` and `glab mr merge` (including the alias `glab mr accept`) to keep merging under manual control.
```
## 2. Full description
This script is an interceptor (a PreToolUse hook for Bash) that implements the "Zero Auto-Merge" policy described in the workflow documentation `docs/agents/git-workflow.md`, in the same way for GitHub (`gh`) and GitLab (`glab`).
The hook's responsibility is to stop the AI agent from completing the lifecycle of a Pull Request or Merge Request on its own by merging it.

`pr_commands.py` makes the decision on the fail-closed principle: merge text is prohibited everywhere, except in commands from a short allowlist of inert programs and in heredoc data that `cat` or `tee` writes to a file. A program that is not in the allowlist is considered able to run its arguments or its input.

- **Lower bound.** The expression `gh\s+pr\s+merge|glab\s+mr\s+(merge|accept)` without word boundaries is searched in `tool_input.command` and in the same command without `\` + newline line continuations. This is a strict superset of the previous substring check. The previous check of the raw payload (`"command"\s*:\s*"[^"]*gh pr merge`) also stays in force: if it matches while the parsed command has no merge text, the call is blocked.
- **Allowlist exception.** A command with merge text is allowed only if the strict lexer accepts it as a whole and every simple command in it is inert:
  - `echo`, `printf`, `cat`, `grep`, `egrep`, `fgrep`, `head`, `tail`, `wc`, `true`, `:` with any arguments — only the exact program name, without a path;
  - text subcommands: `git commit` without global git options before `commit`; `gh issue|pr create|edit|comment|view`; `glab issue|mr create|update|note|view`.

  Everything else is not inert: `sort`, `rg`, `xargs`, any wrappers, shells, interpreters, and unknown programs.
- **Exception for heredoc data.** If the command also has non-inert simple commands (`cd`, `ruff`, `pytest`), merge text is allowed only in the heredoc body that `cat` or `tee` writes to a file as data. The strict lexer must accept the whole command, and the body counts as data only if all these conditions hold:
  - the operator is `<<` or `<<-` without a descriptor number, and the delimiter is quoted: `'EOF'`, `"EOF"`, or `\EOF`;
  - the body belongs to a simple command whose program is exactly `cat` or `tee` (without a path and wrappers), and this command is not joined to its neighbors by a pipeline `|` or `|&`;
  - the writer has only heredoc redirections and stdout output to a file (`>`, `>>`, `>|`, including `1>`), and at least one such output exists; `tee` also needs its own stdout output, for example `> /dev/null`. Another descriptor number, `>&`, `<&`, `<`, `<>`, `<<<`, `&>`, and a word with `{` in the writer's argv (this is how bash writes `{fd}>`) cancel the exception;
  - every written file (the output target, and for `tee` also its operands; after `--` any word counts as an operand) is an ordinary path: without `*`, `?`, `[`, `{`, not in `/dev/` (except `/dev/null`), and not in `/proc/`; the name after the last `/` is not empty, does not consist of digits, and does not equal `stdin`, `stdout`, `stderr`, because after `cd /dev/fd` or `cd /dev` such a name opens a shell descriptor; the directories `/dev/`, `/proc/` and these names are compared case-insensitively;
  - no other part of the command names the written file: the file name (after the last `/`) is not a substring of the words and redirection targets of other simple commands or of the bodies of other heredocs, no pattern with `*`, `?`, `[` specifies it, and no other part contains a word with `{` (brace expansion, `find -exec … {}`). The pattern is checked with a margin. Each part is cut into tokens by spaces, `;`, `&`, `|`, `<`, `>`, `(`, `)`, `=`, `,`, quotes, `$'`, `$"`, `\`, and the backtick; a token with `*`, `?`, or `[` after the last `/` names the file if it matches any substring of its name: `*` is any string, `?` is any character, and everything from the first `[` to the end of the token is exactly one arbitrary character, without parsing the bracket syntax. So characters that the splitting cut off from the pattern do not hide a match, and the check remains a superset of bash pathname expansion: `bash m.[!A-Z]h`, `bash m.[^x]h`, `sh m.[[:lower:]]h`, `sh m.[[=s=]]h`, `sh m.[[.s.]]h`, `bash m.[s=]h` are blocked; after writing `a,b.sh` or `a=b.sh`, `bash a,b.?h`, `bash ?,?.sh`, and `bash a=b.?h` are blocked; and in a heredoc body that a shell executes, `bash 'm'.s?`, `bash m\.s?`, and `` echo `bash m.s?` `` are blocked. The price of the margin is extra blocks: `*.py` also names `a.pyc`, and `test_[0-9].py` names any name with `test_` and a character after it. A token without `*`, `?`, `[` after the last `/` (`tests/*/body`) names only a file with the same name; the extglob forms `?(…)`, `+(…)`, `@(…)`, `!(…)` count as `*(…)`. The name and the pattern are compared case-insensitively: on a case-insensitive file system (Windows, macOS) `M.SH` and `m.sh` are one file, so `cat > M.SH <<'EOF'` … `EOF`, followed by `bash m.sh` or `bash *.SH`, is blocked. The pattern is compared both with the original name and with its `casefold`: `casefold` turns `ß` into `ss`, and `?` matches one character, so `bash ?.sh` after writing `ß.sh` is also blocked. An inert command outside a pipeline whose redirections only read or go to `/dev/null` does not name a file: `gh pr comment 7 --body-file body.md` only publishes its text;
  - no other part of the command names the writer program as a separate word (`alias cat=bash`, `hash -p /bin/bash cat`) and no `exec` reassigns the descriptors of the shell itself.

  Only bodies that passed all checks are cut out of the command text. The command is allowed if the remaining text has no merge text and the words of the strict lexer do not form a merge, including one split by quotes.
- **The strict lexer** understands a small subset of bash: single quotes; double quotes with the escapes `\"`, `\\`, and `` \` ``; the `\` + newline continuation; `\` escaping outside quotes; separators — newline, `;`, `&`, `&&`, `|`, `||`, `|&`; redirections, including those with a descriptor number and `>|`; the here-string `<<<`; heredoc `<<` and `<<-` with a quoted or unquoted delimiter. Heredoc bodies are read in operator order starting from the line after the nearest newline outside quotes, `<<-` strips leading tabs; the bodies do not enter argv.
- **Outside the subset — block.** The lexer refuses, and a command with merge text is blocked, if it contains `$` outside single quotes (including inside double quotes), a backtick (except `` \` `` in double quotes), a `#` comment, `(`, `)`, `{`, `}`, `!` and other reserved words in command position, `;;`, an assignment before the program, process substitution, an unclosed quote, a heredoc without a delimiter, or a heredoc body with an unquoted delimiter that contains `$`, a backtick, or `\`.
- **Merge split by quotes.** If the command has no merge text, the call is still blocked when the words of the command (from the strict lexer, and outside its subset from shlex) form `gh pr merge` or `glab mr merge`/`accept`, or when one word contains merge text after quote removal.
- A payload that does not parse as JSON or has no string `tool_input.command` is checked by the lower bound against the raw text; text only in other payload fields (for example, `tool_input.description`) is not taken into account.
- Python runs on every call, without a fast path. The command is allowed only with code `0` and the word `allow` in the output of `pr_commands.py`: a missing Python, any non-zero code, and a partial copy of the module give code `2`.

These pass, for example: `cat <<'EOF' … EOF` (including with `> notes.md`), `echo`, `printf`, and `grep` with merge text in the arguments, `git commit -m '…'`, `gh pr comment … --body '…'`, and also the chain `cd /repo && cat > body.md <<'EOF' … EOF` followed by `ruff format` and `pytest`, and `tee body.md <<'EOF' > /dev/null … EOF`. These are blocked: mentions in a substitution (`git commit -m "$(cat <<'EOF' … )"`), in an argument of a program outside the allowlist, in backticks, and in a comment; a heredoc on the stdin of a shell or interpreter (`bash <<'EOF'`, `python3 - <<'EOF'`); running a written file (`cat <<'EOF' > m.sh … EOF`, followed by `bash m.sh`, `bash *.sh`, or `cat m.sh | bash`); a writer in a pipeline (`cat <<'EOF' > f | bash`); `tee` without its own stdout redirection; and a heredoc with an unquoted delimiter in a chain with non-inert commands.

Residual limitations are the forms that hide merge text both from the previous check and from the current one: obfuscation, indirection (through variables or another program), scripts in files, shell aliases and functions, `gh alias`/`glab alias`, and API calls (`gh api`, `glab api`). The exception for heredoc data does not notice that a neighboring command executes the written file without naming it: `pytest` finds `conftest.py`, `make` reads `Makefile`, `git commit` runs hooks from `.git/hooks`, a program reads a written configuration file, `ls | xargs` iterates over a directory. The allowlist already had the same class (`cat > .git/hooks/pre-commit <<'EOF'` … `EOF`, then `git commit`), and a write and a run in two Bash calls bypass both checks. A file name without `*`, `?`, `[`, and a program name or `exec` that is assembled only at run time (quotes or `\` inside a word in a heredoc body, `eval` or `bash -c` with quotes inside a word, interpreter code) count as obfuscation; a pattern with `*`, `?`, `[` is no longer hidden by such quotes and `\`.
## 3. Contracts
- **Input (Input/Brief):** The JSON payload of the Bash tool call through standard input (`stdin`); the decision is made from the field `tool_input.command` and from the previous raw-payload check.
- **Output (Output/Report):**
  - **Success (Allow):** Return code `0` (empty output) if the command has no merge text, every simple command in it is inert by the allowlist, or the merge text stands only in heredoc data that `cat` or `tee` writes to a file under the exception conditions.
  - **Failure (Block):** Return code `2` and a text message in `stderr` that explains the reason for the ban, if the merge text stands outside inert commands and outside heredoc data, if the command goes outside the subset of the strict lexer, or if Python is not found or `pr_commands.py` gave no decision.
