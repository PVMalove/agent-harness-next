# block-pr-merge

## 1. Название и локализация
- **Английское название:** block-pr-merge (PreToolUse Hook)
- **Русский перевод / Суть:**

```text
Запрет автослияния PR/MR: агент не может выполнить `gh pr merge` и `glab mr merge` (включая алиас `glab mr accept`), поэтому слияние остаётся за человеком.
```
## 2. Полное описание
Хук `PreToolUse(Bash)` не даёт агенту слить Pull Request или Merge Request. Так хук проверяет правило "Zero Auto-Merge" из `docs/agents/git-workflow.md`, одинаково для GitHub (`gh`) и GitLab (`glab`).

Решение принимает `pr_commands.py` по принципу fail closed. Merge-текст запрещён везде, кроме двух случаев: команды из короткого allowlist инертных программ и данные heredoc, которые `cat` или `tee` записывает в файл. Программу вне allowlist хук считает способной выполнить свои аргументы или вход.

- **Нижняя граница.** Выражение `gh\s+pr\s+merge|glab\s+mr\s+(merge|accept)` без границ слов хук ищет в `tool_input.command` и в той же команде без переносов `\` + перевод строки. Это строгое надмножество прежней проверки по подстроке. Прежняя проверка сырого payload (`"command"\s*:\s*"[^"]*gh pr merge`) тоже действует: если она срабатывает, а в разобранной команде merge-текста нет, вызов блокируется.
- **Исключение по allowlist.** Команда с merge-текстом пропускается, только если строгий лексер принимает её целиком и каждая её simple command инертна:
  - `echo`, `printf`, `cat`, `grep`, `egrep`, `fgrep`, `head`, `tail`, `wc`, `true`, `:` с любыми аргументами; имя программы должно совпасть точно, без пути;
  - текстовые подкоманды: `git commit` без глобальных опций git перед `commit`; `gh issue|pr create|edit|comment|view`; `glab issue|mr create|update|note|view`.

  Всё остальное не инертно: `sort`, `rg`, `xargs`, любые обёртки, оболочки, интерпретаторы и неизвестные программы.
- **Исключение для данных heredoc.** Если в команде есть и неинертные simple commands (`cd`, `ruff`, `pytest`), merge-текст допускается только в теле heredoc, которое `cat` или `tee` записывает в файл как данные. Строгий лексер должен принять всю команду. Тело хук считает данными, только если выполнены все условия:
  - оператор `<<` или `<<-` без номера дескриптора, разделитель в кавычках: `'EOF'`, `"EOF"` или `\EOF`;
  - тело принадлежит simple command, программа которой ровно `cat` или `tee` (без пути и обёрток), и эта команда не соединена с соседними конвейером `|` или `|&`;
  - у писателя только перенаправления heredoc и вывод stdout в файл (`>`, `>>`, `>|`, в том числе `1>`), причём хотя бы один такой вывод есть; `tee` тоже нужен свой вывод stdout, например `> /dev/null`. Другой номер дескриптора, `>&`, `<&`, `<`, `<>`, `<<<`, `&>` и слово с `{` в argv писателя (так bash записывает `{fd}>`) снимают исключение;
  - каждый записанный файл (цель вывода, а у `tee` ещё её операнды; после `--` операндом считается любое слово) задан обычным путём: без `*`, `?`, `[`, `{`, не в `/dev/` (кроме `/dev/null`) и не в `/proc/`; имя после последнего `/` не пустое, не состоит из цифр и не равно `stdin`, `stdout`, `stderr`, потому что после `cd /dev/fd` или `cd /dev` такое имя открывает дескриптор оболочки; каталоги `/dev/`, `/proc/` и эти имена сравниваются без учёта регистра;
  - другая часть команды не называет записанный файл: имя файла (после последнего `/`) не входит подстрокой в слова и цели перенаправлений других simple commands и в тела других heredoc, его не задаёт шаблон с `*`, `?`, `[`, и ни в одной другой части нет слова с `{` (раскрытие фигурных скобок, `find -exec … {}`). Шаблон хук проверяет с запасом. Каждую часть хук режет на токены по пробелам, `;`, `&`, `|`, `<`, `>`, `(`, `)`, `=`, `,`, кавычкам, `$'`, `$"`, `\` и обратной кавычке; токен с `*`, `?` или `[` после последнего `/` называет файл, если совпадает с любой подстрокой его имени: `*` означает любую строку, `?` любой символ, а всё от первой `[` до конца токена ровно один любой символ, без разбора синтаксиса скобок. Поэтому символы, которые разбиение отрезало от шаблона, совпадение не прячут, и проверка остаётся надмножеством раскрытия путей bash: блокируются `bash m.[!A-Z]h`, `bash m.[^x]h`, `sh m.[[:lower:]]h`, `sh m.[[=s=]]h`, `sh m.[[.s.]]h`, `bash m.[s=]h`. После записи `a,b.sh` или `a=b.sh` блокируются `bash a,b.?h`, `bash ?,?.sh` и `bash a=b.?h`, а в теле heredoc, которое исполняет оболочка, блокируются `bash 'm'.s?`, `bash m\.s?` и `` echo `bash m.s?` ``. За запас хук платит лишними блокировками: `*.py` называет и `a.pyc`, а `test_[0-9].py` называет любое имя с `test_` и символом после него. Токен без `*`, `?`, `[` после последнего `/` (`tests/*/body`) называет только файл с тем же именем; extglob `?(…)`, `+(…)`, `@(…)`, `!(…)` считается как `*(…)`. Имя и шаблон сравниваются без учёта регистра: на файловой системе без учёта регистра (Windows, macOS) `M.SH` и `m.sh` означают один файл, поэтому `cat > M.SH <<'EOF'` … `EOF`, а затем `bash m.sh` или `bash *.SH` блокируются. Шаблон сравнивается и с исходным именем, и с его `casefold`: `casefold` превращает `ß` в `ss`, а `?` совпадает с одним символом, поэтому `bash ?.sh` после записи `ß.sh` тоже блокируется. Инертная команда вне конвейера, у которой перенаправления только читают или ведут в `/dev/null`, файл не называет: `gh pr comment 7 --body-file body.md` только публикует его текст;
  - другая часть команды не называет отдельным словом программу писателя (`alias cat=bash`, `hash -p /bin/bash cat`) и `exec`, который переназначает дескрипторы самой оболочки.

  Из текста команды хук вырезает только тела, прошедшие все проверки. Команда разрешается, если в оставшемся тексте merge-текста нет и слова строгого лексера не образуют merge, в том числе разбитый кавычками.
- **Строгий лексер** понимает небольшое подмножество bash: одинарные кавычки; двойные кавычки с экранированием `\"`, `\\` и `` \` ``; перенос `\` + перевод строки; экранирование `\` вне кавычек; разделители: перевод строки, `;`, `&`, `&&`, `|`, `||`, `|&`; перенаправления, в том числе с номером дескриптора и `>|`; here-string `<<<`; heredoc `<<` и `<<-` с разделителем в кавычках или без. Тела heredoc лексер читает в порядке операторов со строки после ближайшего перевода строки вне кавычек, `<<-` снимает ведущие табуляции; в argv тела не попадают.
- **Вне подмножества хук блокирует.** Лексер отказывает, и команда с merge-текстом блокируется, если в ней есть `$` вне одинарных кавычек (в том числе в двойных), обратная кавычка (кроме `` \` `` в двойных кавычках), комментарий `#`, `(`, `)`, `{`, `}`, `!` и другие зарезервированные слова в позиции команды, `;;`, присваивание перед программой, подстановка процесса, незакрытая кавычка, heredoc без разделителя или тело heredoc с разделителем без кавычек, где есть `$`, обратная кавычка или `\`.
- **Merge, разбитый кавычками.** Если merge-текста в команде нет, хук всё равно блокирует вызов, когда слова команды (строгого лексера, а вне его подмножества shlex) образуют `gh pr merge` или `glab mr merge`/`accept` либо одно слово содержит merge-текст после снятия кавычек.
- Если payload не разбирается как JSON или не содержит строковой `tool_input.command`, хук проверяет нижней границей сырой текст. Текст только в других полях payload (например, `tool_input.description`) не учитывается.
- Хук запускает Python на каждый вызов, без быстрого пути. Команда разрешается только при коде `0` и слове `allow` в выводе `pr_commands.py`: отсутствие Python, любой ненулевой код и частичная копия модуля дают код `2`.

Пропускаются, например, `cat <<'EOF' … EOF` (в том числе с `> notes.md`), `echo`, `printf` и `grep` с merge-текстом в аргументах, `git commit -m '…'`, `gh pr comment … --body '…'`, а также цепочка `cd /repo && cat > body.md <<'EOF' … EOF` с последующими `ruff format` и `pytest` и `tee body.md <<'EOF' > /dev/null … EOF`. Блокируются упоминания в подстановке (`git commit -m "$(cat <<'EOF' … )"`), в аргументе программы вне allowlist, в обратных кавычках и в комментарии, heredoc на stdin оболочки или интерпретатора (`bash <<'EOF'`, `python3 - <<'EOF'`), запуск записанного файла (`cat <<'EOF' > m.sh … EOF`, а затем `bash m.sh`, `bash *.sh` или `cat m.sh | bash`), писатель в конвейере (`cat <<'EOF' > f | bash`), `tee` без своего перенаправления stdout и heredoc с разделителем без кавычек в цепочке с неинертными командами.

Остаточные ограничения. Эти формы прячут merge-текст и от прежней проверки, и от нынешней: обфускация, косвенность (через переменные или другую программу), скрипты в файлах, alias и функции оболочки, `gh alias`/`glab alias` и вызовы API (`gh api`, `glab api`). Исключение для данных heredoc не замечает, что соседняя команда исполняет записанный файл, не называя его: `pytest` находит `conftest.py`, `make` читает `Makefile`, `git commit` запускает hooks из `.git/hooks`, программа читает записанный конфигурационный файл, `ls | xargs` перебирает каталог. Тот же класс уже был у allowlist (`cat > .git/hooks/pre-commit <<'EOF'` … `EOF`, затем `git commit`), а запись и запуск в двух вызовах Bash обходят обе проверки. Имя файла без `*`, `?`, `[`, имя программы или `exec`, которое собирается только при выполнении (кавычки или `\` внутри слова в теле heredoc, `eval` или `bash -c` с кавычками внутри слова, код интерпретатора), относится к обфускации; шаблон с `*`, `?`, `[` такие кавычки и `\` уже не прячут.
## 3. Контракты
- **Вход (Input/Brief):** JSON-payload вызова инструмента Bash через стандартный ввод (`stdin`); решение принимается по полю `tool_input.command` и по прежней проверке сырого payload.
- **Выход (Output/Report):**
  - **Успех (Разрешение):** код `0` и пустой вывод, если в команде нет merge-текста, каждая её simple command инертна по allowlist или merge-текст стоит только в данных heredoc, которые `cat` или `tee` записывает в файл по условиям исключения.
  - **Отказ (Блокировка):** код `2` и сообщение в `stderr` с причиной запрета, если merge-текст стоит вне инертных команд и вне данных heredoc, если команда выходит за подмножество строгого лексера, если Python не найден или `pr_commands.py` не дал решения.
