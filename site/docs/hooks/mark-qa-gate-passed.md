# mark-qa-gate-passed

## 1. Название и локализация
- **Английское название:** mark-qa-gate-passed
- **Русский перевод / Суть:**

```text
Отметка об успешном прохождении QA-гейта
```
## 2. Полное описание
Хук `mark-qa-gate-passed.sh` срабатывает после успешной команды Bash (`PostToolUse(Bash)`) и отмечает, что текущее состояние checkout прошло все проверки качества (QA-гейт).

Хук проверяет, совпадает ли выполненная команда с последней командой из `qa_gate_commands` в `.harness/project.json`. QA-гейт останавливается на первой ошибке, поэтому успех последней команды значит, что прошли и все предыдущие. Конфигурацию хук ищет по порядку: в checkout команды, в корне проекта (`CLAUDE_PROJECT_DIR`), в основном worktree репозитория. Так он находит её и в linked worktree, где gitignored-каталога `.harness/` нет. Если конфигурации нет нигде, хук ничего не делает.

Совпадением хук считает только прогон всей последней команды:

- её simple commands идут подряд с теми же разделителями, либо оболочка (`bash`, `sh`, `zsh`, `dash`, `ksh`, `powershell`, `pwsh`) получает её целиком строкой команды: `bash -lc '<команда>'` или `-Command '<команда>'`, как её запускает навык `qa-gate`;
- перед командой нет `||`, после неё стоит только `&&`, и она не запущена в фоне. Иначе успех вызова Bash не означает её успех (`<команда> || true`, `<команда>; true`, `<команда> | tail`).

Хук не ставит маркер ещё в двух случаях:

- команда только содержит текст QA-команды, например запускает более узкий выбор тестов `<команда> test_one`;
- команда выходит за подмножество bash, которое разбирает строгий лексер hooks: подстановка `$(...)`, присваивание перед программой `FOO=1 <команда>`.

Если команда совпала, хук вычисляет идентификатор состояния checkout: хеш текущего коммита (`HEAD`) и хеш незакоммиченных изменений (`git diff HEAD`). Эту строку он записывает в маркер `.claude/.qa-gate/passed`. Перед созданием Pull Request хук `require-qa-gate.sh` проверяет, что маркер есть и совпадает с текущим состоянием.

Этот хук служит запасным путём. Обычно маркер записывает сам навык `qa-gate` через скрипт `record-qa-gate-pass.sh`, потому что навык работает в изолированном контексте. Хук нужен, когда агент запускает команды QA-гейта напрямую через Bash в основной сессии.

Хук подключён только в `.claude/settings.local.json`: там `PostToolUse` срабатывает лишь после успешной команды. Во втором coding runtime хук не подключён: тот вызывает `PostToolUse` и после команды с ненулевым кодом выхода, а кода выхода в payload нет (см. [install-and-update.md](install-and-update.md)).
## 3. Контракты
- **Вход (Input/Brief):** JSON выполненного вызова Bash через `stdin`: команда и `cwd`.
- **Выход (Output/Report):** если команда совпала, хук создаёт или обновляет маркер `.claude/.qa-gate/passed` со строкой `<HEAD_hash>:<diff_hash>`. Код возврата `0`. Хук учётный: в [конверте hook-response](hook-response.md) его ошибка даёт предупреждение, а не блокировку.
