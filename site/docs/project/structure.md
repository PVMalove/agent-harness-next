# Структура проекта

`harness init` оставляет в проекте проверяемый снимок: скиллы, hooks и контракты, с которыми проект
работает автономно. После установки исходный репозиторий harness не нужен, его можно удалить.
Обновления ставит отдельная команда.

## Дерево проекта

```text
<repo>/
├── .harness/            # управляемый снимок: lock, реестр скиллов, конфигурация
│   ├── docs/            # контракты для агентов: technical-english и project-memory
│   ├── skills/          # установленные скиллы
│   ├── project.json     # язык, ветки, проверки, hooks, память
│   └── orchestration/   # появляется вместе с capability backend-orchestration
├── .agents/             # skills, видимые через нативный поиск скиллов
├── .claude/             # rules, agents, hooks и локальные настройки runtime
├── docs/
│   ├── agents/          # операционные руководства для агентов
│   └── adr/             # архитектурные решения проекта (ведут скиллы)
├── AGENTS.md            # кросс-рантаймовый контракт проекта
├── CLAUDE.md            # точка входа для Claude Code
└── CONTEXT.md           # словарь терминов и доменная модель (ведут скиллы)
```

`docs/adr/` и `CONTEXT.md` установщик не создаёт: их пишут скиллы `domain-modeling` и
`grill-with-docs`, когда в проекте появляются термины и решения.

Содержимым `.harness/` управляет установщик. `diff` показывает правки managed-файлов, и молча их
никто не перезаписывает. Seed-файлы проект правит под себя: при обновлении они сохраняются, пока их
замену не запросят явно.

## Контракты для агентов

Установщик кладёт в проект операционные руководства
`docs/agents/{agent-prompt,artifacts,git-workflow,issue-tracker,test-author,triage-labels,worktrees}.md`. По
ним агент выполняет работу: ветки и коммиты, работа с трекером, метки, временные артефакты, worktree и
тестовая зона.

Руководство по выпуску и русские описания субагентов остаются в исходном репозитории harness: в
целевом проекте они либо не нужны, либо зависят от его собственных правил.

## Что не устанавливается

| Что | Где живёт | Почему |
| --- | --- | --- |
| Архитектурные решения | Исходный репозиторий harness | Контракты самого инструмента, а не проекта |
| Спецификации и архивы задач | Трекер проекта | Живой источник правды не копируется |
| Диаграммы | Исходный репозиторий harness | Иллюстрации для разработчика инструмента |
| Описания скиллов на русском | Исходный репозиторий harness | Документация для человека, не инструкция агенту |
| Руководства для разработчика | Исходный репозиторий harness | Публичные версии живут на этом сайте |

## Снимок и обновление

Установка копирует снимок и записывает lock с хешами файлов, которыми управляет harness. Затем
`diff` показывает расхождения с закреплённым снимком, а `update` ставит новую версию capability и
сохраняет локальные правки, пока их не попросят перезаписать.

Установленный проект не зависит от клона инструмента. Хеши в lock описывают то, что установлено в
проект, даже если исходный репозиторий с тех пор изменился.
