# Структура проекта

`harness init` оставляет в проекте проверяемый снимок: набор скиллов, hooks и контрактов, с которым
проект живёт автономно. Исходный репозиторий harness после установки не нужен — его можно удалить, а
обновления приходят отдельной командой.

## Дерево проекта

```text
<repo>/
├── .harness/            # управляемый снимок: lock, реестр скиллов, конфигурация
│   ├── docs/            # контракты для агентов: technical-english и project-memory
│   ├── skills/          # установленные скиллы
│   ├── project.json     # язык, ветки, проверки, hooks, память
│   └── orchestration/   # появляется вместе с capability backend-orchestration
├── .agents/             # skills, видимые через нативный поиск скиллов
├── .claude/             # rules, agents, hooks и локальные настройки runtime
├── docs/
│   ├── agents/          # операционные руководства для агентов
│   └── adr/             # архитектурные решения проекта
├── AGENTS.md            # кросс-рантаймовый контракт проекта
├── CLAUDE.md            # точка входа для Claude Code
└── CONTEXT.md           # словарь терминов и доменная модель
```

Содержимое `.harness/` управляется установщиком: правки managed-файлов видны в `diff` и не
перезаписываются молча. Seed-файлы, которые проект правит под себя, при обновлении сохраняются,
пока не запрошена их замена явно.

## Контракты для агентов

В проект разворачиваются операционные руководства
`docs/agents/{artifacts,git-workflow,issue-tracker,test-author,triage-labels,worktrees}.md`. Это
документы, по которым агент выполняет работу: ветки и коммиты, работа с трекером, метки, временные
артефакты, worktree и тестовая зона.

Руководство по выпуску и описания субагентов остаются в исходном репозитории harness: в целевом
проекте они либо не нужны, либо зависят от его собственных правил.

## Что не устанавливается

| Что | Где живёт | Почему |
| --- | --- | --- |
| Архитектурные решения | Исходный репозиторий harness | Контракты самого инструмента, а не проекта |
| Спецификации и архивы задач | Трекер проекта | Живой источник правды не копируется |
| Диаграммы | Исходный репозиторий harness | Иллюстрации для разработчика инструмента |
| Описания скиллов на русском | Исходный репозиторий harness | Документация для человека, не инструкция агенту |
| Руководства для разработчика | Исходный репозиторий harness | Публичные версии живут на этом сайте |

## Снимок и обновление

Установка копирует снимок и записывает lock с хешами файлов, которыми управляет harness. Дальше
`diff` показывает расхождения с залоченным снимком, а `update` подтягивает новую версию capability и
сохраняет локальные правки, пока их не попросят перезаписать.

Установленный проект живёт независимо от клона инструмента: хеши в lock описывают ровно то, что
установлено, а не то, что лежит в исходном репозитории на текущий момент.
