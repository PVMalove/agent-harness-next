# Hooks

Hook проверяет действие агента до того, как оно выполнится, и может его заблокировать. Правило из
инструкции агент может не заметить. Правило в hook возвращает отказ до выполнения команды.

Профиль задают только в конфигурации проекта, в ключе `hook_policy`. Переменные окружения и
параметры инструментов на выбор профиля не влияют.

## Профили

| Поведение | `minimal` | `standard` | `strict` |
| --- | --- | --- | --- |
| Критические guard-ы | да | да | да |
| Ограниченный прогон проверок | предупреждение | блокирует | блокирует |
| Уведомление об изменении влияния при первом касании рискованного пути | нет | предупреждение | предупреждение |
| Напоминание о неотчитанных точечных проверках | нет | да | да |
| Повторная проверка чувствительных путей при каждом касании | нет | нет | да |
| Отказ на границах высокого риска | нет | нет | да |

Без ключа `hook_policy` действует `standard`. Его блокирующий набор совпадает с прежним
поведением, поэтому существующий проект не меняет режим без явного решения. Эскалация только
повышает профиль для указанных путей или ролей. Эскалацию слабее базового профиля валидатор
отвергает.

## Критические guards

Эти проверки блокируют в любом профиле, включая `minimal`:

- **Защищённые ветки.** Агент не может коммитить и пушить напрямую в ветку выпуска и в
  `integration/*`. Работа идёт в issue-ветке, защищённые ветки обновляет человек через мерж.
- **Merge pull request.** Hook всегда блокирует команду мержа: мержит только человек.
- **Публичная атрибуция.** Hook блокирует следы автоматизированного исполнителя в сообщениях
  коммитов, заголовках и телах PR/MR. В тексте трекера он блокирует только атрибуцию.
- **Защита политики.** Hook блокирует запись агента в настройки и каталоги hooks и правку ключа
  `hook_policy`.

## Таблица hooks

| Hook | Событие | Что блокирует |
| --- | --- | --- |
| `protect-hook-policy.sh` | `PreToolUse(Bash, Write, Edit, MultiEdit, NotebookEdit)` | Правку настроек и каталогов hooks и изменение ключа политики |
| `block-direct-master.sh` | `PreToolUse(Bash)` | Коммит и push в защищённую ветку; разрешает только создание новой integration-ветки |
| `block-pr-merge.sh` | `PreToolUse(Bash)` | Любую команду мержа PR/MR; команду, которую не удалось разобрать, тоже блокирует |
| `block-public-attribution.sh` | `PreToolUse(Bash)` | Запрещённые сведения в сообщениях коммитов, заголовках и телах PR/MR и в файлах, переданных как тело |
| `check-branch-name.sh` | `PreToolUse(Bash)` | Создание ветки, имя которой не соответствует `branch_pattern` |
| `check-worktree-branch-name.sh` | `PreToolUse(EnterWorktree)` | То же правило имени для worktree-инструмента |
| `block-scratch-outside-docs-tasks.sh` | `PreToolUse(Write, Edit)` | Временные артефакты вне разрешённых каталогов; заголовок PR и комментарии пишутся только через файл в разрешённом месте |
| `require-qa-gate.sh` | `PreToolUse(Bash)` | Создание PR/MR, если QA не проходил или провалился для текущего дерева |
| `require-bounded-check.sh` | `PreToolUse(Bash)` | Полный прогон набора проверок без обёртки сводкой; точечный тест не блокируется |
| `block-dangerous-git.sh` | `PreToolUse(Bash)` | Разрушительные операции: `reset --hard`, `clean -f`, `branch -D`, `checkout .`, `restore .` |
| `impact-first-touch.sh` | `PreToolUse(Write, Edit)` | Ничего: предупреждает о первом касании пути, влияние которого не вычисляется по графу |
| `sensitive-path-recheck.sh` | `PreToolUse(Write, Edit)` | Ничего: в `strict` сообщает о каждой правке чувствительного пути и пишет запись доказательства |
| `targeted-check-reminder.sh` | `PreToolUse(Write, Edit)`, `Stop`, `SubagentStop` | Ничего: в `standard` и `strict` напоминает отчитать точечные проверки, если файлы менялись после отчёта |
| `runtime-autostart.sh` | `PreToolUse(Bash)`, `Stop`, `SubagentStop` (только Claude Code) | Ничего: перед командой coordinator запускает или переиспользует `harness-runtime serve`, в конце хода освобождает владельца; при сбое выводит предупреждение с причиной и журналом |
| `count-skill-usage.sh` | `PreToolUse(Skill)` | Ничего: считает частоту вызова скиллов |
| `mark-qa-gate-passed.sh` | `PostToolUse(Bash)` | Ничего: записывает маркер прохождения QA для прямого запуска команд |

В проект с включённой ролью test-author отдельно ставится guard тестовой зоны
(`test-author-guard.py`, подключён во frontmatter агента). Он не даёт реализующей роли менять тесты.
В стандартную установку guard не входит.

## Политика и аудит

При approval coordinator закрепляет digest политики hooks. Поэтому смена профиля видна как
изменение контракта. Если проверенный план описывает одну политику, а исполнение идёт при другой,
это заметно до публикации.

Профиль меняет человек, когда правит конфигурацию проекта. Агент не может изменить ни настройки
hooks, ни ключ политики: это блокируется во всех профилях. Команды восстановления
(`ledger lock-status`, `qa clear-stale-lease`, `batch rewind`, `dispatch cancel`) не блокирует ни один
профиль, иначе из отказа не было бы выхода.
