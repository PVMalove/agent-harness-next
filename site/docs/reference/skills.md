# Скиллы

Capability задаёт состав скиллов. Часть апстримных скиллов переопределена под этот workflow, часть
добавлена как first-party, остальные поставляются как есть. Переопределение — это намеренная правка
поверх апстрима, а не локальный дрейф: в сравнении с залоченным снимком такие скиллы видны как
изменённые, и это ожидаемо.

## Проектные переопределения

| Скилл | Что изменено |
| --- | --- |
| `triage` | Namespaced-таксономия меток состояния и отдельная ось режима исполнения вместо апстримных имён. |
| `to-spec` | Публикует эпик в состоянии проработки, согласует и создаёт integration-ветку от базовой ветки проекта, пишет спецификацию файлом и публикует её из файла. |
| `to-tickets` | Связывает дочерние тикеты родительской связью трекера, ставит блокировку заблокированному тикету и не переписывает эпик. |
| `implement` | Гейты с approval, отдельные роли, обязательные проверки review и QA, issue-ветка от integration-ветки, ранний отчёт о блокере и маршрут восстановления. |
| `ask-matt` | Учитывает выбор разработчика: двухосевое ревью либо переход к коммиту и push. |
| `code-review` | Выводит отчёт на языке из конфигурации проекта. |
| `diagnosing-bugs` | Перед гипотезами ищет прошлые исправления через read-only поиск по памяти проекта, если память включена; воспроизведение остаётся обязательным. |
| `tdd` | Добавляет рефакторинг после зелёного теста и проверяемые правила теста: одно поведение на согласованном шве, независимое ожидание, детерминированные часы и RNG, та же СУБД для SQL. |
| `grilling` | При включённой памяти ищет прецеденты до первого раунда проектирования; указатели не отменяют явное согласие на артефакт. |
| `grill-me` | Тонкая обёртка над проектной версией с единым финальным выбором: спецификация или правки плана. |
| `grill-with-docs` | Та же обёртка плюс ведение глоссария и архитектурных решений. |
| `wayfinder` | Тикеты карты несут режим исполнения и состояние; занятие тикета ставит его в работу. |

## Инженерные

| Скилл | Только вручную | Описание |
| --- | --- | --- |
| `ask-matt` | да | Роутер: какой скилл или поток подходит под ситуацию. |
| `grill-with-docs` | да | Интервью с учётом существующего кода; параллельно ведёт глоссарий и архитектурные решения. |
| `triage` | да | Issue или PR через машину состояний триажа: категория, проверка, бриф. |
| `improve-codebase-architecture` | да | Ищет возможности углубления модулей, показывает отчёт, затем прожарка по выбранной. |
| `setup-matt-pocock-skills` | да | Разовая настройка трекера, таксономии меток и раскладки доменных документов. |
| `tdd` | нет | Цикл red → green → refactor. |
| `to-spec` | да | Синтез обсуждения в спецификацию и публикация в трекер. |
| `to-tickets` | да | Декомпозиция спецификации на вертикальные слайсы со связями блокировки. |
| `wayfinder` | да | Карта решений для работы, не помещающейся в одну сессию. |
| `implement` | да | Конвейер с ролями и гейтами. |
| `prototype` | нет | Одноразовый прототип для проектного вопроса. |
| `research` | нет | Исследование по первоисточникам; результат — файл в репозитории. |
| `domain-modeling` | нет | Доменная модель: глоссарий и архитектурные решения. |
| `codebase-design` | нет | Словарь «глубоких» модулей: интерфейс, шов, адаптер, тестируемость. |
| `code-review` | нет | Двухосевое ревью: Standards и Spec. |
| `resolving-merge-conflicts` | нет | Разрешение конфликта в процессе merge или rebase. |
| `wizard` | нет | Интерактивный bash-визард для шагов, которые может выполнить только человек. |
| `diagnosing-bugs` | нет | Цикл диагностики сложных дефектов и деградаций производительности. |

## Продуктивность

| Скилл | Только вручную | Описание |
| --- | --- | --- |
| `grill-me` | да | Проработка плана без привязки к коду. |
| `grilling` | нет | Стресс-тест плана, решения или идеи. |
| `handoff` | да | Передача контекста другой сессии или модели. |
| `teach` | да | Объяснить новый концепт в контексте этого проекта. |
| `to-questionnaire` | да | Превратить нерешённый вопрос в анкету для другого человека. |
| `wait-what` | да | Повторное изложение последнего ответа агента другой формулировкой. |
| `writing-for-agents` | нет | Документы для агентов: скиллы и инструкции проекта. |

«Только вручную» означает, что скилл вызывается как команда и не выбирается моделью самостоятельно.

## Проектные дополнения

Эти скиллы добавлены специально для этой сборки — в апстриме их нет.

### Проектные скиллы (first-party)

| Скилл | Описание |
| --- | --- |
| `qa-gate` (skill) | Полный локальный прогон качества из `qa_gate_commands` в изолированном форке перед PR. |
| `to-guide` (skill) | Руководство с промптами для ручной реализации `hitl`-тикета. |
| `setup-labels` (skill) | Разово создаёт и обновляет метки в трекере по словарю проекта. |
| `to-pull-requests` (skill) | Ручной путь публикации и завершения: проверка ветки, тело PR/MR, закрытие тикета. |
| `fast-implement` (skill) | Однопроходный путь без гейтов для мелких задач. |
| `delivery-stats` (skill) | Отчёт по стоимости закрытого эпика: токены, кеш, объём кода, сравнение с базовой линией. |
| `architect` (skill) | Ручное сравнение архитектурных вариантов; при включённой памяти ищет прецеденты. |
| `pr-composer` (subagent) | Заполняет тело PR по шаблону проекта и возвращает путь к файлу. |

`pr-composer` поставляется как субагент, а не как скилл: его вызывает сессия или другой скилл, сам
он не выбирается моделью.
