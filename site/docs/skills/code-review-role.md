# Code Review: ревью кода

## 1. Название и локализация

- **English:** Code Review
- **Русский (1:1):**

```text
Ревью кода
```

## 2. Полное описание

Code Review проверяет изменение независимо и только читает код. Эта роль обязательна для каждого риск-триггера из её манифеста: API и публичные контракты, миграции схемы и данных, outbox и очереди, маршрутизация схем сообщений, транзакции, авторизация и безопасность, конкурентность и повторные попытки, retry и DLQ. Другие изменения могут пройти через неё после явной оценки риска. Роль не меняет production code и не интегрирует проверяемую ветку.

Роль смотрит diff и Context Package, а не всё дерево. Если пакета не хватает, она эскалирует блокер и не обходит репозиторий целиком. В отчёте она фиксирует diff и исходное требование как доказательства и возвращает две независимые оси: Standards и Spec. Их нельзя сводить в один балл или заменять одну другой. Пока нет отчёта по обеим осям, координатор не завершает high-risk batch: отсутствующий отчёт блокирует batch.

Отклонение от буквы brief роль записывает как finding, но не требует из-за него retry автоматически. Если реализация функционально равна названной в brief или безопаснее её, роль ставит `warning` с этой оценкой. Тогда координатор может записать `override-warning` и сохранить кандидата. В `review.recommendation` роль ставит `accept` или `retry`. Какие severity вызывают автоматический retry, решает настройка `auto_retry_min_severity`.

## 3. Контракты

- **Вход (Input/Brief):** неизменяемый brief, зафиксированный diff или диапазон коммитов, исходная спецификация, стандарты проекта и список применимых риск-триггеров.
- **Выход (Output/Report):** раздельные findings Standards и Spec с severity; зафиксированные доказательства diff и требования; остаточные риски, блокеры и отметка, что production code не менялся.
