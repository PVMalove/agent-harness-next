# /code-review — ревью по двум осям

`/code-review` проверяет diff от зафиксированной точки (коммит, ветка, тег или целевая ветка PR/MR)
по двум осям в параллельных субагентах и показывает отчёты рядом. Навык только сообщает находки и
код не меняет; прогон проверок проекта — задача `/qa-gate`.

Если пользователь называет PR или MR, точкой отсчёта становится его целевая ветка: навык читает
целевую ветку и ветку-источник, выполняет `git fetch origin <target>` и сравнивает с
`origin/<target>`. Текущий checkout должен быть веткой-источником; иначе навык сообщает об этом
пользователю и ветку не переключает.

- **Standards:** соответствует ли код документированным стандартам репозитория. Поверх них
  действует базовый список code smells Фаулера из `references/smell-baseline.md`. Стандарт
  репозитория важнее списка, а каждый smell — суждение, а не жёсткое нарушение.
- **Spec:** реализует ли код исходный тикет или спецификацию.

## Источники спецификации

Навык ищет тикет по ссылкам в коммитах или в названном PR/MR, по пути из аргумента или по файлу
спецификации под `docs/`, `specs/` или `.scratch/`. Если у тикета есть `## Parent: #<epic>`, навык
читает и эпик. Разделы спецификации `## Non-Goals & Rejected Alternatives` и
`## Surgical File & Contract Changes` вместе с разделами тикета `## Out of scope`,
`## Contract touchpoints` и `## Relevant Files (Discovery Context)` показывают, где изменение
вышло за рамки задачи. Без спецификации ось Spec пропускается, и это видно в отчёте.

## Результат

Отчёты осей выводятся под заголовками `## Standards` и `## Spec` без объединения и ранжирования, в
конце — по одной строке на ось. Язык отчёта задаёт `language` из `.harness/project.json`. Для
маршрута `/implement` (Context Package координатора, delta-review) правила лежат в
`references/gated-route.md`.
