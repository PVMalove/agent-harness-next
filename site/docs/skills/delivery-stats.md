### Статистика поставки

**Цель:** после того как эпик и его дочерние тикеты закрыты, покажите, во что на самом деле обошлась поставка: отдельной HTML-панелью и кратким резюме в этой сессии.

Скилл только читает. Он читает локальные транскрипты сессий, историю git этого репозитория и трекер задач, записывает один HTML-файл и ничего никуда не отправляет.

#### Маршрут

Инструмент поставляется с harness: `.harness/reporting/delivery_stats.py`. Если его нет, в проекте не установлена capability, которая его поставляет. Сообщите об этом и не пишите замену здесь.

```bash
python .harness/reporting/delivery_stats.py --repo . --epic <номер> \
  --html .harness/.sandboxes/reports/delivery-stats/epic-<номер>.html
```

Добавьте `--json`, если разработчику нужны исходные числа, а не резюме. `--rates <file>` заменяет тарифную карточку, `--base <ref>` заменяет базу diff.

После завершённого сопоставимого эпика сохраните baseline с версией формата и передайте его при отчёте по следующему эпику. Сравнение попадёт и в отчёт в терминале или JSON, и в HTML-панель:

```bash
python .harness/reporting/delivery_stats.py --repo . --epic <baseline-epic> \
  --save-baseline .harness/.sandboxes/reports/delivery-stats/epic-<baseline-epic>.baseline.json
python .harness/reporting/delivery_stats.py --repo . --epic <current-epic> \
  --baseline .harness/.sandboxes/reports/delivery-stats/epic-<baseline-epic>.baseline.json \
  --html .harness/.sandboxes/reports/delivery-stats/epic-<current-epic>.html
```

#### Процедура

1. **Определите эпик.** Его называет разработчик. Если он назвал дочерний тикет, всё равно запустите инструмент для этого тикета и скажите, что так и сделали: тикет без подзадач инструмент считает областью из одного тикета.
2. **Проверьте тарифную карточку, прежде чем обещать деньги.** Стоимость появляется, только если есть `.harness/reporting/rates.json` и в нём есть цены на использованные модели. Встроенного прайс-листа нет намеренно: цены зависят от тарифа и меняются со временем. Если файла нет, скопируйте `.harness/reporting/rates.example.json`, попросите разработчика вписать свои тарифы, а пока сообщите всё остальное. Не придумывайте число и не называйте цену, которую не прочитали из этого файла.
3. **Сохраните или сравните baseline, когда это полезно.** Сохраняйте только завершённый эпик, сопоставимый с оцениваемым. Сравнение сохраняет для каждого провайдера с обеих сторон атрибуцию `exact` или `estimated`. Разница появляется, только если telemetry есть с обеих сторон.
4. **Запустите инструмент** и запишите панель в `.harness/.sandboxes/reports/delivery-stats/`.
5. **Сообщите резюме** в этой сессии: закрытые тикеты, объём кода, токены по моделям, распределение кэша, стоимость (если есть тарифы) и путь к HTML.
6. **Передайте оговорки как есть, не сглаживайте их.** В них смысл отчёта:
    - Работа Claude Code атрибутируется **точно**: каждая запись транскрипта содержит свою ветку.
    - Работа Codex атрибутируется **приблизительно**. В его журналах нет ветки, только рабочий каталог и время. Поэтому его итог охватывает этот репозиторий в окне активности эпика и может включать несвязанную работу того же периода. Приводя это значение, всегда говорите «оценка».
    - Всё, для чего инструмент не нашёл источника, помечено `нет данных`. Передавайте это как отсутствующие данные: не округляйте до нуля и не заполняйте по памяти.
    - ADR считается добавленным, только если коммит, который первым добавил файл, входит в один из pull request эпика. Поэтому squash-merged pull request занижает счёт. Говорите об этом, только если разработчик спросит, почему число кажется низким.
7. **Предложите прикрепить отчёт.** Панель остаётся локальным файлом. Публиковать её в эпике решает разработчик, автоматически это не делается.

#### Границы

Не правьте транскрипты, тарифную карточку или историю git, чтобы число выглядело лучше. Не добавляйте цены, модели или тикеты, которых инструмент не сообщил. Если инструмент завершился с ненулевым кодом, покажите его stderr и остановитесь: частичная статистика, выданная за полную, хуже, чем никакой.

</div>

## 3. Контракты

- **Вход (Input/Brief):** номер завершённого эпика или дочернего тикета; необязательные параметры `--json`, `--rates`, `--base`, `--save-baseline` и `--baseline`.
- **Выход (Output/Report):** HTML-панель в `.harness/.sandboxes/reports/delivery-stats/` и краткий отчёт: закрытые тикеты, объём кода, токены, кэш, стоимость (если её удалось рассчитать) и оговорки о точности.
