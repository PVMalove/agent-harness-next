name: setup-labels

### Настройка меток

`gh issue edit --add-label` и `gh issue create --label` падают, если метки ещё нет: `gh` никогда не создаёт её сам. GitLab ведёт себя наоборот: `--label` с отсутствующей меткой молча создаёт её с цветом GitLab по умолчанию. Поэтому метка, которую поставили тикету до запуска скилла, остаётся с неправильным цветом. Скилл создаёт каждую метку, которая нужна таксономии triage репозитория, с её каноническим цветом. Запускайте его до первого `/to-spec` или `/to-tickets`.

#### Процесс

1. **Прочитайте таблицы.** Возьмите каждую строку `Label` / `Color` из `docs/agents/triage-labels.md`: таблицы таксономии (категория, режим выполнения, состояние workflow, контекстные метки) и дополнение Wayfinder. Нужны только имя и hex-цвет, столбец `Applied by` пропустите. На GitHub пропустите и `Meaning`, а на GitLab возьмите его первое предложение как описание метки. Если файла нет, попросите пользователя запустить `harness update`: команда создаст файл из шаблонов харнесса. Затем остановитесь.
2. **Покажите план.** Перечислите каждую метку, которую скилл создаст или обновит, с её цветом. Получите подтверждение мейнтейнера до изменения трекера: шаг меняет общее состояние репозитория, и для него действует та же дисциплина, что для любого шага, который меняет трекер (см. `docs/agents/issue-tracker.md`).
3. **Примените.**
   - **GitHub:** для каждой метки выполните `gh label create "<name>" --color "<hex>" --force`. С `--force` команда идемпотентна: она обновляет цвет существующей метки вместо ошибки и больше ничего в ней не трогает. Issues с этой меткой не меняются.
   - **GitLab:** у CLI нет `--force` для создания метки, поэтому сначала сравните план с существующими метками. `<host>`, `<project-url>` и `<project-id>` заданы в `docs/agents/issue-tracker.md` → GitLab → Conventions.
     - Один раз прочитайте существующие метки: `GITLAB_HOST=<host> glab api --paginate projects/<project-id>/labels`. Нужен постраничный API, потому что собственный список меток CLI возвращает только одну страницу. Каждая запись содержит `id`, `name` и `color`.
     - Метки нет: `glab label create -R <project-url> -n '<name>' -c '<hex>' -d '<description>'`. `<description>`: первое предложение столбца `Meaning` простым текстом, без обратных кавычек и кавычек. Внутри двойных кавычек shell выполнил бы слово в обратных кавычках как команду, а значение в одинарных кавычках не может содержать кавычку.
     - Метка есть, но цвет другой (hex сравнивается без учёта регистра): `glab label edit -R <project-url> --label-id <id> -c '<hex>'`, где `<id>` взят из списка. Меняется только цвет, issues с меткой не меняются.
     - Метка есть с тем же цветом: no-op.
4. **Сообщите результат.** По одной строке на метку: создана, обновлена (цвет изменён) или уже корректна (no-op). Полный план из шага 2 повторно не печатайте.

## 3. Контракты

- **Вход (Input/Brief):** `docs/agents/triage-labels.md` и явное подтверждение мейнтейнера.
- **Выход (Output/Report):** по одной строке результата для каждой метки.
