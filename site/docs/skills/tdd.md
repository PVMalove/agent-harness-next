# tdd: разработка через тесты

Источник: [`SKILL.md`](https://github.com/PVMalove/agent-harness-next/blob/master/skills/first-party/engineering/tdd/SKILL.md).
В `engineering-suite` этот first-party override заменяет одноимённый vendor-скилл. Он задаёт общие
правила тестов для developer и необязательного тест-автора.

Скилл ведёт цикл red → green → refactor на публичном seam, который согласовали заранее. Seam: публичная
граница, на которой вызывающий код видит поведение. Один тест проверяет одно наблюдаемое поведение,
поэтому в нём может быть несколько шагов и несколько проверок, если они описывают это поведение.
Ожидаемое значение берётся из источника, который не зависит от production-кода: литерала, эталонной
fixture с указанным происхождением или независимого oracle. Варианты входных данных оформляются
параметризацией, а не условным выбором ожидания в теле теста.

Внутренние компоненты и value objects в тесте остаются реальными. На внешней границе скилл
различает команду и запрос: для команды тест проверяет отправленный контракт, для запроса подставляет
stub с готовым ответом. Часы и источник случайности тест подменяет детерминированно на границе.
SQL и транзакции тест проверяет на той же СУБД, что в production, в изолированном окружении.
Refactor идёт после Green. Покрытие служит сигналом, а не целью. Политики для flaky-тестов и seed
скилл добавляет, только если проект уже их требует.

Vendor-версия держала примеры и правила подмен в отдельных `tests.md` и `mocking.md`. В first-party
версии правила подмен вошли в `SKILL.md`, а примеры вынесены в
[`examples.md`](https://github.com/PVMalove/agent-harness-next/blob/master/skills/first-party/engineering/tdd/examples.md).

## Необязательный тест-автор

В полном `/implement` исполнитель наследует runtime, model и effort из утверждённого brief developer.
Короткий маршрут берёт явный профиль `test_author` из `.harness/project.json`. Общая проверка:
`python3 -I -B .harness/health/test_author.py preflight --repo <checkout>`. Полный маршрут
добавляет `--brief <путь brief>` и запускает проверку в checkout worker. Вызов разрешает только
ровно `{"status":"ok"}`. Если настроек нет, они неверны, пришёл `runtime_unsupported` или другой
отказ, остаётся обычный TDD с санитизированной причиной, исполнитель не подменяется. Текущий
защищённый адаптер работает через Claude Code и `.claude/hooks/test-author-preflight.sh`. Другие
runtime остаются на обычном TDD, пока для них нет защищённого адаптера.

Полный маршрут с внешним исполнителем Claude вызывает нативный `Agent(test-author)` без overrides
model и effort (`model: inherit`), поэтому сохраняются утверждённые настройки developer. In-process
worker передаёт каждый handoff в `.harness/health/test_author.py run --repo <worktree worker>
--brief <путь brief> --prompt-file <путь>`. Короткий маршрут передаёт каждый prompt-файл в
`.harness/health/test_author.py run --repo . --prompt-file <путь>`: так применяются модель и effort
проекта, даже если текущая сессия работает с другими настройками. Подробнее:
[руководство тест-автора](../agents/test-author.md).

Если preflight успешен, вызывайте субагента перед каждым шагом реализации. Передайте одно
поведенческое требование, один сценарий, согласованный публичный seam, публичные сигнатуры и
существующие fixtures. Не передавайте предложенный алгоритм или фрагмент реализации как основу
ожидания. Субагент пишет только один тест и только в `test_paths`, запускает его через
`.claude/hooks/run-test.sh <test-id>` и коротко по-английски возвращает `status` (`red`,
`needs_skeleton` или `contract_gap`), требование, входные данные, независимый источник ожидания и
id теста. Для `red` он добавляет доказательство Red: JSON runner, проваленное утверждение, ожидание и
фактический результат из `log.txt` запуска. Production-код, скелет и orchestration остаются у
developer. Test-author не получает manifest, dispatch, brief/report, approval и lifecycle ledger.

Сверьте ожидание с требованием до реализации и не ослабляйте принятое ожидание ради Green. Для
`needs_skeleton` напишите только типы и сигнатуры без логики и вызовите субагента снова. Ошибка
компиляции, импорта, fixture или окружения не считается Red. Тест, который сразу зелёный, не
засчитывается как цикл. После трёх неудачных вызовов подряд по одному тесту остановитесь и верните
blocker. Полный протокол описан в `developer.md` ролей оркестрации. Короткий маршрут
`/fast-implement` ведёт тот же протокол в одной сессии. Seam там тот, который разработчик согласовал
до первого теста, а не взятый из brief architect. Если автор недоступен, короткий маршрут остаётся
обычным и называет причину.

`mattpocock-suite` по-прежнему поставляет неизменённый
[vendor-снапшот](https://github.com/PVMalove/agent-harness-next/blob/master/skills/vendor/mattpocock/engineering/tdd/SKILL.md).
