# tdd — Разработка через тесты

Источник: [`SKILL.md`](https://github.com/PVMalove/agent-harness-next/blob/master/skills/first-party/engineering/tdd/SKILL.md).
В `engineering-suite` этот first-party override заменяет одноимённый vendor-скилл и задаёт общие
правила тестов для developer и будущего тест-автора.

Скилл ведёт цикл red → green → refactor на заранее согласованном публичном seam. Один тест
проверяет одно наблюдаемое поведение, поэтому в нём допустимы несколько шагов и несколько проверок,
если они описывают это поведение. Ожидаемое значение берётся из источника, независимого от
production-кода: литерала, эталонной fixture с указанным происхождением или независимого oracle.
Варианты входных данных оформляются параметризацией, а не условным выбором ожидания в теле теста.

Внутренние компоненты и value objects в тесте остаются реальными. На внешней границе скилл
различает команду и запрос: для команды тест проверяет отправленный контракт, для запроса подставляет
stub с готовым ответом. Часы и источник случайности тест подменяет детерминированно на границе,
а SQL и транзакции проверяет на той же СУБД, что в production, в изолированном окружении.
Refactor идёт после Green. Покрытие не служит целью, а flaky- и seed-политики скилл не вводит.

Vendor-версия держала примеры и правила подмен в отдельных `tests.md` и `mocking.md`. В first-party
версии правила подмен вошли в `SKILL.md`, а примеры — в
[`examples.md`](https://github.com/PVMalove/agent-harness-next/blob/master/skills/first-party/engineering/tdd/examples.md).

## Необязательный тест-автор

Исполнитель полного `/implement` наследует runtime/model/effort из утверждённого brief developer;
короткий маршрут выбирает явный профиль `test_author` из `.harness/project.json`. Общая проверка:
`python3 -I -B .harness/health/test_author.py preflight --repo <checkout>`; полный маршрут
добавляет `--brief <путь brief>`. Только `{"status":"ok"}` разрешает вызов. Отсутствие настроек,
`runtime_unsupported` и другие отказы сохраняют обычный TDD с санитизированной причиной,
без подмены исполнителя. Текущий защищённый адаптер использует Claude Code и
`.claude/hooks/test-author-preflight.sh`; выбор runtime не закреплён за ним.

Полный маршрут вызывает нативный `Agent(test-author)` без model/effort overrides (`model: inherit`).
Короткий маршрут передаёт каждый prompt-файл в `.harness/health/test_author.py run --repo .
--prompt-file <путь>`: так применяются настройки проекта, даже если текущая сессия использует
другую модель. Подробнее — [руководство тест-автора](../agents/test-author.md).

При успешном preflight вызывайте субагента перед каждым шагом реализации. Передайте одно
поведенческое требование, один сценарий, согласованный public seam, публичные сигнатуры и
существующие fixtures, но не предложенный алгоритм или фрагмент реализации. Субагент пишет ровно
один тест только в `test_paths`, запускает его через `.claude/hooks/run-test.sh <test-id>` и коротко
по-английски возвращает `status` (`red`, `needs_skeleton` или `contract_gap`), требование, входные
данные, независимый источник ожидания, id теста и для `red` доказательство Red: JSON runner плюс
проваленное утверждение, ожидание и фактический результат из `log.txt` запуска. Production-код,
скелет и orchestration остаются у developer; test-author не получает manifest, dispatch,
brief/report, approval или ledger lifecycle.

Сверьте ожидание с требованием до реализации и не ослабляйте принятое ожидание ради Green. Для
`needs_skeleton` напишите только типы и сигнатуры без логики и повторите вызов. Ошибка компиляции,
импорта, fixture или окружения не считается Red, а сразу зелёный тест не засчитывается как цикл.
После трёх подряд неудачных вызовов по одному тесту остановитесь и верните blocker. Полный
протокол описан в `developer.md` ролей оркестрации. Короткий маршрут `/fast-implement` ведёт тот же
протокол в одной сессии: seam там тот, что разработчик согласовал до первого теста, а не взятый из
brief architect, и недоступный автор сохраняет обычный маршрут с названной причиной.

`mattpocock-suite` продолжает поставлять неизменённый
[vendor-снапшот](https://github.com/PVMalove/agent-harness-next/blob/master/skills/vendor/mattpocock/engineering/tdd/SKILL.md).
