# Приёмочные сценарии фазы реализации

Запускайте каждый сценарий в отдельном тестовом репозитории с `engineering-suite`, в Codex — через
`$fast-implement`, `$to-guide`, `$architect`. До и после каждого ответа снимайте
`git status --short --ignored`, список веток и метки тикета.

## Общие данные

Эпик опубликован `/publish-epic`, дочерние тикеты созданы `/to-tickets`. Тикет 01 — `afk`,
`pipeline::fast`, волна 1, `## Relevant Files (Discovery Context)`: `src/orders.py`,
`tests/test_orders.py`, `## Out of scope`: логирование, критерий
`- [ ] таймаут повторяется -> pytest tests/test_orders.py::test_retry`. Тикет 02 — `hitl`.
Тикет 03 — `pipeline::full`.

| Сценарий | Ввод | Ожидаемый результат |
|---|---|---|
| Выбор по эпику | Вызовите `/fast-implement` с номером эпика. | Взят тикет 01 из волны 1, назначен и переведён в `status::in-progress` до создания ветки. Ветка создана от integration-ветки эпика и запушена. |
| Границы тикета | Попросите заодно добавить логирование в `src/logging.py`. | Агент называет правку вне границ и ждёт одобрения; без него файл не меняется. |
| Проверки | Доведите тикет до конца. | Отчёт `developer` содержит прогон `pytest tests/test_orders.py::test_retry`, lint и typecheck; полного набора тестов нет. Агент спрашивает про ревью, потом разрешение на commit и push, и только предлагает `/to-pull-requests`. |
| Маршруты | Вызовите `/fast-implement` на тикете 03, затем `/implement` без установленной оркестрации. | `/fast-implement` предлагает `/implement`. `/implement` объясняет, что нужна `backend-orchestration` или смена метки на `pipeline::fast`, и не отправляет обратно по кругу. |
| Руководство | Вызовите `/to-guide` на тикете 02. | В карте файлов только пути из `Relevant Files` и `Contract touchpoints`; раздел «Проверка» опирается на `Action -> Verify` или `## Acceptance & Verification Criteria`. |
| Ревью | Запустите `/code-review` на ветке тикета 01 с правкой логирования. | Spec-ось читает эпик и находит выход за `## Out of scope`. |
| Архитектура | Вызовите `/architect` для решения, которое спецификация уже приняла. | Агент считает решение закрытым и открывает его только при новых данных, прямо об этом говоря. |
